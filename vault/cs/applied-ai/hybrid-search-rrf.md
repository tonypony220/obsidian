# Hybrid search и RRF

---

```
запрос: "GO-2024 elektriciteit certificaten"

   BM25 (по словам)          Dense (по смыслу)
   1. A  счёт GO-2024        1. B  NL-отчёт про электричество
   2. C  реестр              2. A  счёт GO-2024
   3. D  ...                 3. E  FR-отчёт про électricité
            └─────────── RRF ───────────┘
            1. A   (высоко в обоих)
            2. B
            3. C, E, D ...
   → один список → top-k → LLM
```

**TL;DR:** Hybrid search — запустить [[bm25]] и [[dense-retrieval-embeddings]] на один запрос и слить два списка в один. RRF (Reciprocal Rank Fusion) — способ слить: смотрит на *место* документа в каждом списке, а не на score.

## Зачем вообще два поиска

Они ошибаются на разном:
- BM25 нашёл счёт с кодом `GO-2024`, но не нашёл французский отчёт — там другие слова
- dense нашёл французский отчёт по смыслу, но код `GO-2024` для него просто шум

Вместе находят больше нужного.

## Зачем RRF: проблема склейки

Дальше по пайплайну (LLM, reranker) нужен **один** список и **один** top-k. Как из двух списков сделать один?

Наивно — сложить score. Но шкалы разные:

| Документ | BM25 score | Dense score (косинус) | Сумма |
|---|---|---|---|
| A | 14.7 | 0.81 | 15.5 |
| C | 12.1 | 0.40 | 12.5 |
| D | 3.0 | 0.35 | 3.4 |
| B | 0 | 0.83 | 0.83 |

BM25 даёт числа ~10, косинус всегда от 0 до 1 → сумма = почти чистый BM25. Dense фактически выключен, документ B (лучший по смыслу) на последнем месте. Гибрид не работает.

## Как RRF это решает

Выбрасываем score, оставляем только место в списке:

$$
\text{RRF}(d) = \sum_{\text{списки}} \frac{1}{k + \text{место}(d)}, \quad k = 60
$$

Место 1 и место 1 весят одинаково, неважно, 14.7 там или 0.83. Шкалы больше не мешают.

Пример со схемы:

| Документ | место в BM25 | место в dense | RRF |
|---|---|---|---|
| A | 1 | 2 | 1/61 + 1/62 = 0.0325 |
| B | – | 1 | 1/61 = 0.0164 |
| C | 2 | – | 1/62 = 0.0161 |
| E | – | 3 | 1/63 = 0.0159 |

A первый: оба поиска считают его хорошим. B теперь второй, а не последний.

Зачем $k = 60$: без него 1-е место дало бы $1/1 = 1$, а 2-е $1/2$ — первое место забивало бы всё. С $k$ разница между соседними местами мягкая.

## Ограничение

RRF всё равно отдаёт top-k. Что не попало ни в один из двух списков — потеряно. Для задач «найти все доказательства» это главная дыра.

## Концепция шире

- **Ансамбли в ML:** голосование моделей с разными ошибками точнее любой одной
- **Метапоиск:** агрегаторы склеивали выдачи разных поисковиков по местам, не по очкам
- **Выборы:** ранжированное голосование (Borda count) — сумма по позициям в бюллетенях

Общее везде: когда шкалы несравнимы, сравнивай порядок.
