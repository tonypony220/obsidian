# Iterative retrieval

moc: [[applied-ai-moc]]
back: [[query-decomposition]]
next:
- [[react-agentic-search]]

---

```
вопрос ─▶ поиск #1 ─▶ "выбросы считает дочка Colvea BV"
                         │ LLM: значит, нужны документы Colvea BV
          поиск #2 ◀─────┘
             │
             ▼  "отчёт Colvea BV, Scope 2 = 410 т"
          хватает? ── да ──▶ ответ
             │ нет
             ▼
          поиск #3 ...   (стоп по лимиту шагов)
```

**TL;DR:** Поиск в несколько раундов: найденное на шаге N используется для запроса на шаге N+1. Нужно, когда следующий вопрос нельзя сформулировать, пока не прочитал ответ на предыдущий.

## К чему относится

Обёртка над [[retrieval]], как и [[query-decomposition]]. Разница:

| | Query decomposition | Iterative retrieval |
|---|---|---|
| Подвопросы | все сразу, заранее | по одному, по ходу |
| Зависит от найденного | нет | да |
| Число поисков | фиксировано | заранее неизвестно |

Термин из статей: **multi-hop** — ответ требует нескольких «прыжков» через разные документы (A → B → ответ). Известные варианты: IRCoT (поиск после каждого шага рассуждения), Self-Ask (модель сама задаёт себе уточняющий вопрос).

## Пример multi-hop

«Выполнена ли цель по безопасности?»
1. Поиск → журнал инцидентов: 3 травмы
2. Чтобы посчитать частоту, нужны отработанные часы → новый поиск по `hours worked`
3. Часы в Excel HR, но только для одного завода → поиск по второму заводу

Шаг 2 и 3 нельзя было придумать до шага 1.

## Когда остановиться

Главная сложность. Варианты: LLM решает «информации достаточно», лимит шагов, повтор уже найденного. LLM склонна остановиться рано, если первые находки выглядят убедительно.

Если модель ещё и сама выбирает *инструмент* (поиск, открыть файл, посчитать) — это уже [[react-agentic-search]].
