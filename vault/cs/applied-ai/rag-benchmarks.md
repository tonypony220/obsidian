**TL;DR:** Бенчмарк — фиксированный набор вопросов с правильными ответами, на котором сравнивают системы. HERB проверяет RAG на корпоративных данных. Главный вывод из него: с идеальными доказательствами модель набирает 86, с обычным RAG 21 → почти вся потеря в поиске, а не в модели.

## Бенчмарк ≠ метрика

- **метрика** — формула: recall@k, accuracy ([[retrieval-metrics]])
- **бенчмарк** — данные + правильные ответы + выбранные метрики
- **retrieval metric** — нашли ли нужные куски
- **final-task metric** — правильный ли итоговый ответ. У HERB указан этот: средний score ответа, шкала 0–100

Цифры разных бенчмарков нельзя сравнивать между собой: разные данные и метрики.

## HERB

Heterogeneous Enterprise RAG Benchmark. ~39 000 артефактов: документы, Slack, встречи, GitHub, ссылки. Есть **unanswerable** вопросы — ответа в корпусе нет, правильно сказать «не знаю».

## Oracle — что это

Oracle evidence = модели дают **ровно правильные доказательства** из разметки, без поиска. Это нереализуемо на практике, но показывает **потолок**: лучше с такой моделью не будет.

- идеал 100, oracle 85.8 → 14 пунктов теряет сама модель (рассуждение, чтение)
- oracle 85.8, hybrid 20.6 → 65 пунктов теряет поиск
- oracle evidence = 0.2% корпуса: нужное — крошечная доля, найти её и есть задача

## Unanswerable

Hybrid RAG распознал только ~25% вопросов без ответа — в остальных уверенно что-то ответил. Это ровно проблема `needs review` → [[abstention-needs-review]].

## Классические evidence-бенчмарки

| Бенчмарк | Что проверяет |
|---|---|
| FEVER | вердикт по [[claims]] (supports/refutes/NEI) + полный набор доказательств |
| HoVer | то же, но доказательства в 2–4 документах; засчитано только если найдены все |
| HotpotQA | multi-hop ответ + supporting facts |

FEVER и HoVer ближе всего к задаче с objectives: засчитывается не ответ, а ответ **вместе с полным набором доказательств**.
