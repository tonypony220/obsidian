```
  текст стр. 8:                          схема (Pydantic / JSON Schema):
  "Scope 1 bedroeg 2 117 ton CO2e"       scope_1_t: float | null
           │                             year: int
           │  LLM + схема                quote: str
           ▼                             page: int
  {"scope_1_t": 2117, "year": 2024,
   "quote": "Scope 1 bedroeg 2 117 ton", "page": 8}
           │
           ▼ валидация: тип ок? цитата реально есть в тексте?
         ✔ / ✘ → повторить
```

**TL;DR:** LLM не пишет свободный ответ, а заполняет заранее заданную схему полей: значение, единица, год, цитата, страница. Результат — данные, которые можно проверить кодом и передать в правило.

## К чему относится

Мост между чтением и решением в [[neuro-symbolic-evaluation]]: neuro-часть. Классическое название области — information extraction (IE). Источник текста может быть любым: фрагменты из [[rag]], документ целиком ([[long-context-reading]]), каждый кусок ([[exhaustive-scan]]).

## Как добиться правильного формата

- **Structured outputs / JSON mode** у API: модель физически может выдать только JSON по схеме
- **Instructor + Pydantic:** описываешь схему классом Python, при ошибке валидации — автоматический повтор
- **LangExtract (Google):** извлечение с привязкой к точному месту в исходном тексте

## Что класть в схему

| Поле | Зачем |
|---|---|
| значение + единица | `2117`, `tCO2e` — нормализовать потом кодом |
| период | 2024 или 2025, иначе смешаются годы |
| цитата дословно | проверить кодом, что она реально есть в документе |
| файл + страница | для `proving_document` |
| `null` разрешён | «не нашёл» лучше, чем выдуманное число |

## Чего не даёт

Правильный JSON ≠ правильные факты. Схема гарантирует форму, а не полноту: модель может вернуть 13 категорий из 15 в идеальном формате. Проверка цитаты ловит выдумку, но не пропуск. Пропуск ловят правило-проверкой полноты и [[abstention-needs-review]].
