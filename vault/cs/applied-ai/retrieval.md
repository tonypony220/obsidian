```
                       Retrieval (поиск)
        ┌──────────────────┼────────────────────┐
  Sparse / lexical      Dense              Гибрид
  (по словам)           (по смыслу)        (оба сразу)
  ├ Boolean             ├ bi-encoder        └ BM25 + dense → RRF
  ├ TF-IDF              │  эмбеддинги
  ├ BM25  ← стандарт    └ ColBERT
  └ SPLADE (обученный)     (вектор на каждое слово)
```

**TL;DR:** Retrieval — общее название для «по запросу найти релевантные документы и упорядочить их». Это не один метод, а семейство. Dense retrieval — это и есть поиск по эмбеддингам, одна из веток.

## Что общего у всех методов

Любой retrieval делает одно и то же:
1. считает **score** — число «насколько документ подходит к запросу»
2. сортирует документы по score
3. отдаёт **top-k** — первые k (например, 10)

Методы отличаются только тем, *как* считают score.

## Две главные ветки

| | Sparse / lexical | Dense |
|---|---|---|
| Что сравнивает | слова запроса и документа | векторы смысла |
| Почему «sparse/dense» | вектор размером со словарь (100 000), почти все нули | вектор из ~1000 чисел, все ненулевые |
| Методы | Boolean, TF-IDF, [[bm25]], SPLADE | [[dense-retrieval-embeddings]], ColBERT |
| Находит | точные коды, имена, номера | синонимы, перефразы, другие языки |
| Нужна нейросеть | нет (кроме SPLADE) | да |

## Sparse-методы по порядку появления

- **Boolean** — документ либо содержит все слова, либо нет. Без ранжирования
- **TF-IDF** — score = частота слова × его редкость. Первый «умный» ранг
- **BM25** — TF-IDF плюс насыщение повторов и штраф за длину. Стандарт с 1990-х, по умолчанию в Elasticsearch
- **SPLADE** — нейросеть сама решает, какие слова и с каким весом добавить в sparse-вектор (например, добавит «emissions» к тексту про CO₂)

## Как это связано с RAG

RAG = retrieval + generation: сначала retrieval находит фрагменты, потом LLM отвечает по ним. Retrieval — это «R» в RAG.
