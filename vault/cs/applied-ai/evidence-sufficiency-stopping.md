```
  Обычный агент:          "мне кажется, хватит" ─▶ стоп

  По claims:
     claims: c1 ✔  c2 ✔  c3 ✔  c4 ?  c5 ?
                                 │
             gaps = {c4, c5} ────┘  пусто? ── да ──▶ стоп
                    │ нет
                    ▼
     запросы из gaps: "Scope 3 category 2 capital goods"
                    ▼
                  поиск ─▶ обновить статусы ─▶ снова
```

**TL;DR:** Evidence sufficiency — вопрос «достаточно ли уже найденного, чтобы ответить». В [[iterative-retrieval]] и [[react-agentic-search]] LLM обычно решает это на глаз. HALT и S2G-RAG привязывают остановку к явному списку [[claims]]: стоп только когда у каждого claim есть доказательство.

## Проблема stopping

Stopping — решение «прекратить поиск». Две ошибки:
- **рано:** первые находки убедительны, недостающий факт не искали
- **поздно:** лишние поиски, деньги и время (redundant search)

LLM чаще ошибается первым способом.

## HALT

Из статьи, Findings EMNLP 2026 (по пересказу в ресерче; сам не проверял):
1. по вопросу заранее генерирует **ожидаемые hop claims** — какие промежуточные факты нужны
2. ищет, отмечает, какие claims поддержаны найденными evidence
3. разрешает остановку, когда **поддержан каждый требуемый claim**

Результат у авторов: меньше лишних поисков при почти той же точности ответа на multi-hop QA.

## S2G-RAG

Gap = пробел, недостающая информация.
1. **controller** (LLM-оценщик) смотрит на найденное и решает: достаточно или нет
2. если нет — пишет **структурированные gap items**: что именно не хватает («нет данных по категории 2 за 2024»)
3. каждый gap превращается в следующий поисковый запрос
4. повторять до пустого списка gaps

## Разница

| | HALT | S2G-RAG |
|---|---|---|
| Список нужного | claims заранее | gaps по ходу |
| Упор | когда остановиться | что искать дальше |

## Почему «узкая задача»

Оба работают, только если **список нужных claims известен или правильно сгенерирован**. Пропущенный claim никто не ищет, и остановка «всё покрыто» будет ложной. Полноту открытого корпуса они не гарантируют. Для objectives это хорошая новость: условия уже записаны в тексте цели, список claims почти готов.
