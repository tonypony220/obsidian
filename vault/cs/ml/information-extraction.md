```
 "Заказ 4412 от Иванова, доставка в Лион до 5 мая"
        │ extraction
        ▼
 { order_id: "4412", person: "Иванов", city: "Лион", deadline: "05-05" }
```

**TL;DR:** из свободного текста достаются именованные сущности и поля заранее заданной схемы, то есть текст превращается в данные.

| Подход | Суть | Когда |
|---|---|---|
| Правила / regex | шаблоны для форматов | жёсткие форматы: даты, id, e-mail |
| NER-модель | помечает каждый токен: PERSON, ORG, LOC | типовые сущности, много текста, нужна скорость |
| LLM + схема | промпт + JSON schema на выходе | гибкие поля, мало разметки |

- NER = [[ml-task-types]] «классификация токенов»: каждый токен получает метку класса.
- LLM-экстракция: схема задаёт поля и типы, ответ парсится и валидируется на границе; невалидный ответ = повтор или отказ, а не молчаливая подмена.
- Оценка по каждому полю отдельно: [[precision]] (извлечённое верно), [[recall]] (ничего не пропущено). Одна общая accuracy скрывает слабые поля, см. [[accuracy-paradox]].
- Типичные ошибки LLM: выдуманное значение для отсутствующего поля. Поле должно допускать `null`, а не заставлять модель угадывать.
