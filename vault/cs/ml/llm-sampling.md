```
  "Совет директоров одобрил ..."
          │ модель
          ▼
  распределение следующего токена:
     бюджет 60% │ план 25% │ отчёт 10% │ прочее 5%
          │
          ├─ greedy:    всегда "бюджет"          → один и тот же текст
          └─ sampling:  случайно по этим весам   → "план" в 25% запусков
                          │
                          ▼ выбранный токен добавляется к входу → следующий шаг
```

**TL;DR:** Сэмплирование (sampling) — модель выбирает следующий токен случайно, пропорционально вероятностям, а не всегда самый вероятный. Поэтому один и тот же запрос даёт разные ответы.

## Как выбирается токен

LLM пишет текст по одному токену. На каждом шаге модель выдаёт вероятности для всех токенов словаря (через [[softmax]]). Дальше два режима:

| Режим | Как выбирает | Результат |
|---|---|---|
| greedy | всегда максимум (argmax) | почти детерминированно |
| sampling | случайно, по весам | разные ответы на один вход |

«Случайно по весам» буквально: варианты раскладываются на отрезке $[0, 1]$ длинами своих вероятностей, генератор даёт случайное число $u$, и выбирается вариант, в чей отрезок попало $u$.

| Отрезок | Токен |
|---|---|
| $[0, 0.60)$ | «бюджет» |
| $[0.60, 0.85)$ | «план» |
| $[0.85, 0.95)$ | «отчёт» |
| $[0.95, 1]$ | прочее |

$u = 0.72$ → «план». Один случайный выбор в начале меняет весь дальнейший текст: следующий токен считается уже от другого префикса.

## Зачем случайность

- **greedy зацикливается:** самый вероятный шаг часто повторяет предыдущий → «это важно, потому что это важно, потому что…»
- **greedy плоский:** всегда самое банальное слово
- **лучший шаг ≠ лучший текст:** чуть менее вероятное слово может вести к лучшему продолжению
- **нужно разнообразие:** варианты, идеи, несколько попыток

## Ручки поверх сэмплирования

- [[temperature]] — делает распределение острее или площе
- **top-k** — сэмплировать только из $k$ самых вероятных токенов
- **top-p (nucleus)** — только из самых вероятных, пока их сумма не достигнет $p$ (например, 0.9)

## Следствие: недетерминированность

- одинаковый вход → разные выходы, иногда разного качества
- temperature 0 почти убирает разброс, но **не полностью**: у провайдеров ответы плавают из-за батчинга и вычислений на GPU
- некоторые модели вообще не дают менять temperature

### Для бенчмарков моделей

Один прогон — одна случайная выборка, а не «оценка модели». 78% vs 75% может быть шумом.
- прогнать 3–5 раз, смотреть среднее и разброс
- если одна модель скачет на ±3%, разница между моделями в 3% ничего не значит
- больше задач → шум усредняется
- для отдельной задачи: доля успехов из $k$ попыток (pass@k)

### Для извлечения фактов

Два прогона могут найти разное: в одном пропустил строку, в другом нашёл. Объединение прогонов снижает пропуски, расхождение прогонов — сигнал низкой уверенности ([[abstention-needs-review]]).
