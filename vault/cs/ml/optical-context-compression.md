# Оптическое сжатие контекста

moc: [[ml-moc]]
next:

---

```text
Обычно:       текст → токенизатор → много векторов → LLM
Через зрение: текст → картинка → vision encoder → меньше векторов → LLM
```

**TL;DR:** текст рисуют на изображении, затем обученный кодировщик упаковывает его в короткую последовательность визуальных векторов. Цель — сократить число входных позиций в контексте модели, сохранив информацию.

- В обоих случаях модель получает векторы (embeddings). Особенность — способ их получения и сокращение их числа, а не само хранение векторов.
- Картинка — промежуточное представление; читать его должен специально обученный кодировщик и совместимая языковая модель.
- Пример: DeepSeek-OCR показал около 97% точности восстановления текста при примерно 10-кратном сокращении числа входных токенов в своих OCR-экспериментах. Это сжатие с потерями; качество распознавания не гарантирует качество рассуждений по документу. [Статья](https://arxiv.org/abs/2510.18234)
- **Статус на 2026-10-20:** для сжатия истории чата и расширения контекста LLM — пока исследовательский подход, не устоявшаяся массовая практика. Сам DeepSeek-OCR применяется для распознавания документов; это отдельная задача. [Исходная работа](https://arxiv.org/abs/2510.18234)
- Картинка не обязательна: можно сжимать текстовые векторы напрямую. В последующем сравнительном исследовании лучшие прямые методы превзошли визуальное сжатие; преимущество обхода через изображение не подтвердилось в этих экспериментах. [Сравнение](https://arxiv.org/abs/2512.03643)

Источник обсуждения: [Sam Witteveen — DeepSeek OCR: More than OCR](https://www.youtube.com/watch?v=YEZHU4LSUfU).
