```
 train: [..... текст A .....]      test: [..... текст A' (дубль) .....]
              └──── модель «знает» ответ ────┘
 метрика 0.99 в эксперименте → 0.70 в проде
```

**TL;DR:** в обучение попала информация, которой не будет в момент реального предсказания, поэтому метрика получается красивой и ложной.

| Вид утечки | Пример |
|---|---|
| Дубли между train и test | один и тот же текст/клиент в обеих частях |
| Утечка признака (target leakage) | признак «дата возврата» при предсказании возврата |
| Утечка препроцессинга | scaler / TF-IDF / эмбеддинг-центроид посчитан на всех данных до сплита |
| Утечка времени | случайный сплит временного ряда: обучаемся на будущем |
| Утечка при подборе | порог или гиперпараметры подобраны по test |

- Правило: сплит первым, любой `fit` (нормализация, словарь, [[centroid]]) только на train.
- Проверка: признак подозрительно силён; метрика на test сильно выше, чем в проде; перекрытие train и test по id и по тексту.
- [[cross-validation]] защищает только если препроцессинг внутри каждого fold.
- Группы (один пользователь, один документ нарезан на куски) делить целиком.

## Концепция шире

- Бэктесты в финансах: lookahead bias, данные из будущего.
- Образование: студент видел экзаменационные вопросы заранее.
- Бизнес-метрики: признак вычисляется уже после целевого события.

Общее везде: на этапе оценки доступно то, чего не будет в момент решения.
