# Argmax — какой вариант победил

moc: [[ml-moc]]
next:

- [[llm-sampling]]

---

```
  Gryffindor 0.02 │ Hufflepuff 0.44 │ Ravenclaw 0.00 │ Slytherin 0.00

  max    → 0.44          (само наибольшее значение)
  argmax → Hufflepuff    (КТО его дал)
```

**TL;DR:** Max отвечает «какое наибольшее число», argmax — «у какого варианта это число». В классификации нужен именно argmax: ответ модели — название класса, а не балл.

## Запись

$$
\hat{y} = \arg\max_k \; s_k
$$

$s_k$ — балл (score) или вероятность класса $k$. Читается: «то $k$, при котором $s_k$ наибольшее». В коде: `np.argmax(scores)` возвращает индекс, не значение.

## Где встречается

| Где | По чему берут argmax |
|---|---|
| [[one-vs-all]] | 4 независимые $h_k$ |
| softmax-классификатор | проценты из [[softmax]] |
| LLM, greedy-режим | вероятности всех токенов словаря ([[llm-sampling]]) |

## Argmax не меняется от монотонных преобразований

Если преобразование сохраняет порядок (больше → больше), победитель тот же:
- argmax по логитам = argmax по [[softmax]] от них: экспонента и деление на сумму порядок не меняют
- [[temperature]] не меняет argmax: деление на $T > 0$ сохраняет порядок
- [[sigmoid]] тоже монотонна → в one-vs-all можно сравнивать $z_k$ вместо $h_k$

Поэтому для предсказания класса softmax и сигмоида на самом деле не нужны. Они нужны, когда важны **сами проценты**: для обучения ([[log-loss]]), для порога «уверен / не уверен», для сэмплирования.

## Argmax vs сэмплирование

- argmax: всегда лидер → один и тот же ответ
- sampling: лидер чаще всего, но не всегда → [[llm-sampling]]

Greedy-генерация в LLM — это argmax на каждом шаге.
