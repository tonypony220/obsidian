# Prompting vs RAG vs fine-tuning

```
 Prompting    инструкция + примеры в запросе       ── что делать
 RAG          + найденные документы в запросе      ── что знать
 Fine-tuning  веса модели меняются обучением       ── как себя вести
```

**TL;DR:** это три разных рычага: prompting задаёт задачу, RAG подаёт свежие знания в [[context-window]], fine-tuning меняет поведение модели в весах; идти нужно слева направо по росту стоимости.

| | Prompting | RAG | Fine-tuning |
|---|---|---|---|
| Что меняется | текст запроса | текст запроса + поиск | веса модели |
| Решает | формат, роль, few-shot | актуальные или приватные знания | стиль, формат, узкая задача на объёме |
| Обновить знания | правка промпта | обновить индекс | переобучить |
| Источники в ответе | нет | да, можно сослаться на документ | нет |
| Стоимость старта | минимальная | поиск + индекс | данные + обучение + оценка |

- Выбор по симптому:
  - Не тот формат или тон → prompting (примеры в запросе).
  - Модель не знает ваших данных или они меняются → RAG: [[semantic-search]] + подстановка в промпт.
  - Нужна устойчивость на тысячах однотипных запросов, короче промпт, дешевле вызов → fine-tuning.
- Fine-tuning плохо подходит для «научить фактам»: знания усваиваются ненадёжно и устаревают.
- Рычаги комбинируются: fine-tuned модель + RAG + промпт.
- Любое изменение проверять на отложенной выборке, см. [[train-val-test-split]]; для извлечения полей — [[information-extraction]], для классов — [[text-classification]].

## Концепция шире

- Работа сотрудника: инструкция (prompt), справочник под рукой (RAG), обучение на курсах (fine-tune).
- Базы данных: запрос, индекс/кэш, схема и денормализация.

Общее везде: либо передать знание вместе с задачей, либо встроить его в исполнителя.
