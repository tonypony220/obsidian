# HNSW — иерархический граф для поиска соседей

moc: [[ml-moc]]
next:

---

```text
layer 2:       C────────────────────L
               │                    │
layer 1:       C──────G─────────────L────O
               │      │             │    │
layer 0:   A─B─C─D─E─F─G─H─I─J─K───L─M─N─O─P

верх: мало вершин, дальние переходы
низ:  все вершины, точное уточнение
```

**TL;DR:** HNSW хранит векторы как многослойный граф близких соседей. Поиск быстро проходит разреженные верхние слои, затем уточняет результат на полном нижнем слое.

## Слои и высота

Слои — вложенные графы над одними векторами. Каждый вектор находится на слое `0`; случайно выбранная часть присутствует выше:

```text
level(A) = 0  → слои 0
level(G) = 1  → слои 0, 1
level(C) = 2  → слои 0, 1, 2
```

`level` выбирается случайно, вероятность следующего уровня экспоненциально уменьшается. Высота не означает важность или центр кластера. На верхних слоях вершин меньше, поэтому рёбра между ближайшими доступными вершинами покрывают большие расстояния.

## Построение графа

Граф строится последовательной вставкой векторов. Для нового вектора `x`:

1. Случайно выбрать максимальный уровень `L(x)`.
2. Начать с входной вершины на самом верхнем слое.
3. Переходить к соседу с меньшим `distance(x, neighbor)`, пока улучшение возможно.
4. Спуститься на слой ниже из найденной вершины.
5. На слоях `L(x)..0` исследовать до `efConstruction` кандидатов и выбрать до `M` соседей.
6. Добавить взаимные рёбра; переполненные списки соседей сократить.

Выбор соседей учитывает не только минимальное расстояние, но и разнообразие направлений. Иначе близкие друг к другу кандидаты создадут плотную локальную область без полезных выходов из неё.

## Поиск

Запрос не добавляется в граф. Он начинает с верхней входной вершины:

```text
верхний слой:  крупные переходы к меньшей distance(query, node)
       ↓
средние слои:  уточнение области
       ↓
слой 0:        поиск среди efSearch кандидатов
```

HNSW не делит пространство пополам: у многомерных векторов нет общего порядка `<`. Поэтому, в отличие от бинарного поиска, переход к более близкому соседу не гарантирует исключение половины данных. Результат приближённый; большее исследование графа повышает [[recall]].

## Параметры

| Параметр | Что регулирует | Цена увеличения |
|---|---|---|
| `M` | число рёбер вершины | больше памяти и времени построения |
| `efConstruction` | ширину поиска соседей при вставке | медленнее построение, качественнее граф |
| `efSearch` | ширину поиска для запроса | выше recall, больше latency |

## Кластеров нет

HNSW не вычисляет центроиды и не назначает `cluster_id`. Похожие векторы получают много локальных связей, поэтому плотные области возникают как свойство графа, а не как отдельная структура данных. Для явного разбиения на кластеры используется [[ivf-index]].
