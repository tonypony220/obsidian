```
 1000 писем: 990 нормальных, 10 спам
 модель «всё нормальное»  → accuracy 99%, recall по спаму 0%
```

**TL;DR:** при несбалансированных классах accuracy растёт от «ничего не находить», поэтому хорошая цифра может скрывать бесполезную модель.

| Ловушка | Почему обманывает | Что смотреть |
|---|---|---|
| Accuracy при дисбалансе | мажоритарный класс тянет среднее | [[recall]], [[precision]], [[f1-score]] по классу |
| Среднее по классам | редкий класс тонет | метрики по каждому классу ([[confusion-matrix]]) |
| Метрика на train | модель помнит ответы | val/test, см. [[overfitting]] |
| Лучшая цифра на test после подбора | test использован как val | [[train-val-test-split]] |
| Утечка | в обучении был ответ | [[data-leakage]] |
| Один порог | метрика зависит от порога | [[threshold-sweep]] |

- Вопрос-фильтр: «какая метрика у тривиального бейзлайна (всегда мажоритарный класс)?» Если модель мало превосходит его, цифра ничего не значит.
- Метрика должна отражать цену ошибок: пропуск (FN) и ложная тревога (FP) стоят по-разному.
- Нужна доверительная оценка: разброс по [[cross-validation]], а не одно число.
