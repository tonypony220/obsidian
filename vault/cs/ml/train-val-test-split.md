```
 все данные
 ├── train (60-80%)  ── подгонка весов
 ├── val   (10-20%)  ── выбор гиперпараметров, порога, ранняя остановка
 └── test  (10-20%)  ── ОДИН финальный замер, потом не трогаем
```

**TL;DR:** три выборки отвечают на три разных вопроса; тест, который использовали для подбора, перестаёт быть честной оценкой на новых данных.

| Выборка | Вопрос | Можно смотреть при настройке |
|---|---|---|
| train | чему учимся | да |
| val | какой вариант модели лучше | да |
| test | как будет на новых данных | нет |

- Каждое решение по val («взял другой `lambda`», «сдвинул порог») немного подгоняет модель под val. Test нужен как свежие данные, которых решения не касались.
- Мало данных → [[cross-validation]] вместо одной val; test всё равно держим отдельно.
- Разбиение сохраняет пропорции классов: [[stratified-split]]. Воспроизводимость: [[seed]].
- Для данных во времени делить по времени (train — прошлое, test — будущее), иначе [[data-leakage]].

## Концепция шире

- A/B-тесты: гипотеза и метрика фиксируются до эксперимента.
- Наука: пре-регистрация исследований против подгонки гипотезы под результат.
- Обучение людей: тренировочные задачи vs экзамен.

Общее везде: оценивать нужно на данных, не участвовавших в принятии решений.
