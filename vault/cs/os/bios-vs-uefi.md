```
        BIOS (1981)                      UEFI (~2005)
power ─▶ 16-bit real mode          power ─▶ 32/64-bit сразу
         читает СЕКТОР № 0                  читает ФАЙЛ по имени
         512 Б, печать 0x55AA               \EFI\BOOT\BOOTX64.EFI
         copy → 0x7C00, jmp                 с FAT-раздела (ESP)
         «номер на пластинке»               исполняет PE/COFF (.efi)
```

**TL;DR:** это два поколения прошивки — контракта «как машина находит и запускает первый чужой код». BIOS знает только «сектор» и «прыгнуть»; UEFI — маленькая ОС, умеющая GPT, FAT и запуск файлов. «Работает / не работает» образ — всегда свойство пары *(образ, прошивка)*.

## BIOS: контракт из 512 байт

Родился с IBM PC (8088, real mode, 1 МиБ адресов). Прочитать сектор 0, проверить `0x55AA`, скопировать в 0x7C00, прыгнуть — всё. Файловых систем и форматов не знает. Сервисы — 16-битные прерывания: INT 13h «прочитай сектор», INT 10h «выведи символ». Дожил до 2010-х на чистой обратной совместимости: каждое железо обязано было грузить DOS.

## Почему произошёл UEFI

- 512 Б на загрузчик → цепочки stage1 → stage1.5 → stage2 у GRUB, костыль на костыле
- 64-битная машина стартует, притворяясь CPU 1978 года; каждый загрузчик пляшет один и тот же танец переключения режимов ([[protected-mode]])
- MBR: 2 TiB максимум, 4 раздела
- нет драйверной модели (сеть/USB/GUI до ОС — вендорские хаки) и нет подписей (буткит пишется в сектор 0 молча)
- триггер: Intel Itanium — real mode отсутствует физически, legacy BIOS невозможен → EFI → стандарт UEFI

UEFI сам понимает GPT, читает FAT (ESP-раздел) и исполняет PE/COFF `.efi` (виндовый формат, не [[elf-format|ELF]]). Загрузка по имени файла, не по магическому сектору. Плюс Secure Boot. Старый путь эмулировала прослойка CSM — из современных прошивок её выпилили, поэтому голая UEFI-Fedora не возит BIOS-модули GRUB: ей самой они не нужны.

| | BIOS (1981) | UEFI (~2005) |
|---|---|---|
| Режим CPU на старте | 16-бит real mode | 32/64-бит сразу |
| Что умеет читать | сектора (INT 13h) | GPT, FAT, файлы |
| Что исполняет | 512 Б с 0x7C00 / [[el-torito]] `0x00` | PE/COFF `.efi` / [[el-torito]] `0xEF` |
| Разметка | MBR (2 TiB, 4 раздела) | GPT |
| Безопасность | нет | Secure Boot |
| В QEMU | SeaBIOS (дефолт) | OVMF |

## Почему KFS сидит на BIOS

- **Сабж:** i386 + GRUB + Multiboot 1 — стандарт BIOS-эпохи; каноническая учебная цепочка BIOS → GRUB → protected mode → `_start`
- **[[vga-text-mode]] — артефакт BIOS-мира:** вся tty пишет в 0xB8000; на чистом UEFI текстового режима нет (framebuffer через GOP, шрифты пикселями)
- **Прозрачность:** BIOS-контракт виден насквозь (512 Б, INT 13h); UEFI прячет пол-машины за своими сервисами
- **QEMU из коробки** — SeaBIOS, нулевая конфигурация

## Концепция шире (старый интерфейс живёт через слой совместимости)

- CSM в UEFI — эмуляция BIOS поверх нового мира
- WOW64 — 32-битные приложения на 64-битной Windows
- Rosetta 2 — x86-бинарники на arm64-Маках
- Терминалы — все «эмуляторы» до сих пор изображают VT100

Общее везде: контракт переживает железо, для которого создан; смена контракта требует переходной эмуляции, и её однажды выпиливают — тогда старые артефакты (наш BIOS-only ISO на UEFI-машине) перестают работать.
