```
          ┌──────────────┐
   A0 ────┤              ├──── D0       A19…A0  «ГДЕ»: только адрес,
   …      │     CPU      │      …               payload'а внутри нет
  A19 ────┤              ├──── D15      D15…D0  «ЧТО»: только данные
          │              │
 MEMR# ───┤              │              управление: читаю/пишу,
 MEMW# ───┤              │              память/порт (IOR#/IOW#)
          └──────────────┘
```

**TL;DR:** цикл шины — интервал, в котором CPU держит адрес на A-пучке, данные на D-пучке и команду на управляющих линиях **одновременно**; выбранная декодером микросхема защёлкивает (запись) или выставляет (чтение) данные. Ничего не едет последовательно — каждый бит стоит на своём личном проводе.

## Куда ведут ножки

Все ножки CPU подключены к одной микросхеме — чипсету; остальное железо — за ним, на вторичных шинах ([[buses-and-controllers]]):

```
        ножки CPU (A, D, управление)
CPU ══════════════════════════ ЧИПСЕТ (декодер + мосты)
                                 ║
                                 ╠═ шина памяти ──── планки RAM
                                 ║
                                 ╠═ PCI-шина:
                                 ║   общие провода адр/данных ─┬─────┬─────┬──
                                 ║                           слот0 слот1 слот2
                                 ║   IDSEL0 ──────────────────┘     │     │
                                 ║   IDSEL1 ────────────────────────┘     │
                                 ║   IDSEL2 ──────────────────────────────┘
                                 ║   (личный провод выбора к каждому слоту)
                                 ╚═ legacy: ROM BIOS, порты…
```

## Запись: `mov word [0xB8000], 0x0734`

Напряжения в момент цикла (все одновременно):

```
A19…A0 = 1011 1000 0000 0000 0000   ← 0xB8000 целиком — только «где»
D15…D0 = 0000 0111 0011 0100        ← 0x0734 целиком — только «что»
MEMW#  = активен                    ← «пишу в память, не в порт»
```

1. Декодер чипсета ест **старшие** биты: `A19..A17 = 101` → chip-select видеокарты; RAM спит (её CS погашен — игнорирует шину)
2. Контроллер карты получает **младшие** 17 бит = `0x18000` — номер ячейки ВНУТРИ его окна (0xB8000 − 0xA0000)
3. Видит MEMW# → защёлкивает D-пучок в свою память по этому смещению

Разделение труда над адресом: старшие биты — выбор микросхемы (декодер), младшие — номер ячейки внутри выбранной (сама микросхема). Ни один бит адреса не является данными — частая ошибка «биты адреса = сообщение» ([[memory-mapped-io]]).

## Чтение

CPU выставляет адрес + MEMR# и **слушает**: данные на D-пучок выставляет выбранная микросхема, CPU защёлкивает. D-пучок двунаправленный (запись — держит CPU, чтение — устройство); A-пучок всегда однонаправленный.

## Каждая инструкция = циклы шины

Другого канала во внешний мир у CPU нет. Fetch самой инструкции — цикл чтения по адресу из EIP; операнд в памяти — ещё цикл. `for(;;)` этапа 1: fetch `nop` @0x100021 → fetch `jmp` @0x100022 → снова. Современно: между ядром и шиной кэши, большинство fetch'ей до проводов не доходит; модель та же.

**EIP — просто число, уходящее на те же A-провода.** Не указатель в «особую память кода» — обычный адрес на оси. Адрес = комбинация напряжений на A-пучке; ось адресов = все комбинации (i386: 2^32). EIP ходит по ОСИ, а не «по планке»: декодер направляет fetch туда, куда назначен диапазон ([[memory-mapped-io]] — три судьбы адреса).
