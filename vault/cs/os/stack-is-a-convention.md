# Stack is a convention

---

```
у CPU нет объекта «стек» — есть регистр esp
и 4 слепые инструкции: push, pop, call, ret

Адреса растут ВВЕРХ по картинке (примерные):
0x108000 ┬─────────────── stack_top: БОЛЬШЕЕ число,
         │ ▓▓ push №1       esp стартует здесь
         │ ▓▓ push №2       каждый push: esp -= 4 →
         │  ↓ растёт вниз   к МЕНЬШИМ адресам («сосулька»)
0x104000 ┴─────────────── stack_bottom: МЕНЬШЕЕ число, дно;
                            ниже — секции самого ядра
```

**TL;DR:** стек — не вещь и не железо, а конвенция: любой кусок обычной RAM становится стеком в тот момент, когда на него указывает esp; push/pop/call/ret слепо работают с памятью по адресу из esp, что бы там ни было.

## Механика

- `push X` = `esp -= 4; память[esp] = X`. `pop` — наоборот. `call` = push адреса возврата + прыжок; `ret` = pop адреса + прыжок обратно.
- Стек растёт **вниз** — поэтому esp ставят на верхнюю границу региона (`stack_top`), и записи идут вниз, внутрь зарезервированного.
- Регион ничем не помечен ([[code-and-data-are-bytes]]): укажи esp на мусор — push будет писать в мусор, молча.

## «Чужой» памяти в ядре нет — есть занятая

Защиты памяти нет вообще: CPU молча исполнит запись по любому адресу. Опасность push мимо стека — не «доступ запрещён» (запрещать некому), а тихая порча: вниз от stack_bottom лежат секции самого ядра (.data, .rodata, .text — свой же код!), ниже 1 МБ — области железа (0xB8000 — экран). Ошибка проявляется не там, где случилась, а позже и в другом месте. В userspace кривой указатель ловит ОС (segfault); здесь ловить некому — стена появится, только когда сами построим paging (KFS_3). Переполнение 16 КБ стека (глубокая рекурсия) — та же тихая порча .data.

Адреса меток назначает линкер по [[linker-script]]; в рантайме меток нет — в `mov esp, stack_top` вшито готовое число.

## Откуда стек у обычной C-программы

Его делает ОС при запуске процесса: выделяет регион, ставит указатель стека, потом прыгает в программу. Поэтому «у C-программы стек уже есть» — о нём позаботился кто-то большой этажом ниже. В ядре этажом ниже никого нет ([[freestanding-environment]]) — поэтому первая инструкция ядра сама назначает стек: `mov esp, stack_top`.

## Почему нельзя «поймать» стек GRUB

На входе в ядро в esp лежит огрызок стека самого GRUB ([[multiboot]]: «ESP не определён») — указывает в память загрузчика, которая уже никем не поддерживается. Не ловим — заменяем целиком.

## Дальше в KFS

- Каждому процессу — свой стек (KFS с процессами): «создать процесс» включает «выделить регион + завести esp»
- Прерывания тоже пишут в текущий стек — ещё одна причина, чтобы esp всегда указывал на валидный регион
