# Code and data are bytes

moc: [[os-moc]]
next:
- [[elf-format]]
- [[multiboot]]

---

```
boot.asm строки          что кладётся в boot.o
────────────────────────────────────────────────────
X equ 0x1BADB002    →    ничего (имя для числа, как #define)
section .multiboot  →    ничего (разметка: «дальше — в эту коробку»)
dd X                →    4 байта ДАННЫХ    ← прочитает GRUB
resb 16384          →    ничего (запись «зарезервируй», .bss)
_start:             →    ничего (имя текущего адреса)
mov esp, stack_top  →    5 байт ИНСТРУКЦИИ ← исполнит CPU
```

**TL;DR:** ассемблерный файл — не «список команд», а рецепт байтов выходного файла; в бинарнике нет разницы между кодом и данными — есть только байты, а смысл им придаёт читатель (CPU исполняет, GRUB читает глазами).

## Ассемблер — тупой переводчик 1:1

Каждая строка либо кладёт байты (данные `dd`/`db`, инструкции), либо ничего не кладёт (метки, `section`, `equ` — имена и разметка). Никакой магии, никакого переупорядочивания — в отличие от компилятора C, который изобретает код (пролог функции, работа со стеком) сам.

## Смысл определяет читатель

- 12 байт `.multiboot` — «данные», потому что их читает [[multiboot|GRUB]]. CPU их не исполнит никогда.
- Байты после `_start` — «код», потому что на них прыгнет CPU.
- Сами по себе байты равноправны: секции [[elf-format]] — это просто способ сказать читателям, где что искать.
- Живой экспонат: `objdump -d kernel.bin` дизассемблирует заголовок как бессмыслицу — `02 b0 ad 1b` (магия 0x1BADB002 little-endian) превращается в `add 0x1bad(%eax),%dh`, а последний байт чексуммы `e4` склеивается с байтом паддинга `66` в «инструкцию» `in $0x66,%al`. Дизассемблер — тоже читатель, и читатель наивный: жуёт любые байты как код.

## Почему boot-код пишут на ASM

C-функция с первой инструкции пользуется стеком (локальные, адрес возврата — компилятор генерит это всегда), а на входе в ядро стека нет и записать регистр `esp` из C нельзя. ASM-мостик делает три вещи: выложить байты заголовка → поставить стек → `call kmain`. Дальше — навсегда C.

## Концепция шире (фон Нейман)

- Эксплойты: подсунуть данные и заставить CPU исполнить их как код — вся классика атак стоит на «байты равноправны»
- JIT: интерпретатор пишет байты как данные, потом объявляет их кодом и прыгает
- Harvard-архитектура (MCU): контрпример — код и данные физически в разных памятях

Общее везде: «код» и «данные» — роли, а не свойства байтов; роль назначает тот, кто читает.
