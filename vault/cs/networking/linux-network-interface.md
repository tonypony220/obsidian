```
        eth0 (интерфейс)
   ┌──────────────────────────┐
   │ state:  UP / DOWN        │ ← ip link set eth0 up/down
   │ MAC:    aa:bb:cc:dd:ee:ff│   (обычно назначается автоматически)
   │ IP(s):  192.168.1.10/24  │ ← ip addr add ... dev eth0
   │         10.0.0.5/24      │   (можно несколько)
   │ MTU:    1500             │
   └──────────────┬───────────┘
                  ▼
           физика / virt
```

Интерфейс = **точка, через которую машина говорит с сетью**. В большинстве случаев это сетевая карта (Ethernet, Wi-Fi), но в Linux это абстракция: интерфейсом может быть и физическая карта, и виртуальное устройство ([[veth-pair]], [[linux-bridge]], [[vxlan]], loopback).

У каждого интерфейса — имя-идентификатор: `eth0`, `wlan0`, `lo`, `eth1`. Через имя команды знают о каком устройстве речь.

## Посмотреть что есть

```bash
$ ip link show
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 ...
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 ...
3: wlan0: <BROADCAST,MULTICAST> mtu 1500 ... state DOWN
```

Это есть у **любой** Linux-машины, не только у роутера. У ноута тоже — просто обычно активен один (`wlan0`). У роутера несколько (`eth0`, `eth1`...).

## UP / DOWN — состояние интерфейса

Интерфейс в Linux может быть **UP** (включён) или **DOWN** (выключен). Как выключатель на розетке.

```bash
ip link set eth0 up        # включить
ip link set eth0 down      # выключить
ip link show eth0          # посмотреть состояние
```

Пока интерфейс DOWN — через него **не идут никакие пакеты**, даже если кабель воткнут и IP назначен. Ядро не считает его живым.

**Зачем выключать вручную:** сменить MAC, изменить MTU, применить новую конфигурацию, отладка.

## Назначение IP — `ip addr add`

```
ip addr add   192.168.1.10/24   dev eth0
   │           │        │         │
 команда     адрес    маска    на какой
                               интерфейс
```

"На интерфейс `eth0` навесь адрес `192.168.1.10` в сети с маской `/24`".

**Важное разделение по уровням OSI:**

```
  L3 (сетевой)  ──▶  IP-адрес        ← ip addr add
  L2 (канальный) ──▶  MAC, Ethernet
  L1 (физический) ──▶  кабель, сигнал ← ip link set up/down
```

Интерфейс без IP физически работает (может слать Ethernet-кадры), но в IP-сети он "немой". Поэтому это **две отдельные операции**: сначала поднять интерфейс, потом навесить IP.

### Несколько IP на один интерфейс

```bash
ip addr add 192.168.1.10/24 dev eth0
ip addr add 10.0.0.5/24 dev eth0       # ещё один
ip addr show eth0                      # оба видны
```

Интерфейс один, а "живёт" в двух сетях. Используется редко, но бывает полезно (сервер виден с нескольких LAN).

## Кто выбирает IP

Короткий ответ: **человек** (админ/инженер), либо **автомат** (DHCP).

### Вручную в лабе

Берёшь адрес из **приватных диапазонов** (RFC 1918) — они не маршрутизируются в интернете, их можно использовать дома и в лабах:

- `10.0.0.0/8` — большой (16 млн адресов)
- `172.16.0.0/12` — средний
- `192.168.0.0/16` — классика домашних сетей

BADASS использует `30.1.1.0/24` — это публичный диапазон, но на изолированных GNS3-узлах никто извне туда не полезет, поэтому не страшно.

### В корпоративной сети

**Сетевой архитектор** заранее продумывает план: "офис — `10.1.0.0/16`, серверная — `10.1.1.0/24`, воркстейшены — `10.1.2.0/24`". Потом уже назначают конкретные адреса.

### Автоматически

- **DHCP** — хост запрашивает, сервер выдаёт из пула (например Wi-Fi роутер дома держит `192.168.1.100–200`).
- **SLAAC** (IPv6) — хост сам вычисляет адрес на основе префикса, полученного от роутера.

В BADASS **всё вручную** — субъект требует "No IP address should be configured by default" (образ голый, IP настраивается в GNS3 после импорта).

## CIDR-маска `/N` — что это

Короткая форма для: "сколько первых бит IP — это идентификатор сети, сколько остальных — идентификатор хоста внутри сети".

```
  192.168.1.10/24

  Биты:     11000000.10101000.00000001.00001010
            └──────── 24 бита ─────────┘└ 8 бит ┘
              СЕТЬ (одинакова у всех    ХОСТ (уникален
              в этой подсети)            для машины)
```

| Маска | Сеть | Хостов |
|---|---|---|
| `/24` | `192.168.1.0` | 254 (`.1–.254`) |
| `/16` | `192.168.0.0` | 65534 |
| `/8` | `10.0.0.0` | 16 млн |
| `/32` | один адрес | 1 (точечный маршрут) |
| `/0` | любой адрес | все (default route) |

Маска задаёт **границу сети**. Две машины `192.168.1.10/24` и `192.168.1.20/24` видят друг друга напрямую (одна подсеть). А `192.168.1.10/24` и `192.168.2.10/24` — в разных сетях, между ними нужен роутер.

## Зачем вообще нужна маска в `ip addr add`

Частый вопрос: "я же указал адрес `10.0.0.5` — зачем ещё маска?"

Адрес говорит **"кто ты"**, маска говорит **"где границы твоей сети"**. Один и тот же адрес `10.0.0.5` может жить в разных сетях:

```
  10.0.0.5/24  →  сеть 10.0.0.0 – 10.0.0.255      (254 соседа)
  10.0.0.5/16  →  сеть 10.0.0.0 – 10.0.255.255    (65k соседей)
  10.0.0.5/28  →  сеть 10.0.0.0 – 10.0.0.15       (14 соседей)
```

### Зачем ядру знать границы

Когда машина хочет отправить пакет на `10.0.0.100`, ядро решает **главный вопрос форвардинга**:

> "Этот адрес — мой сосед (в одной подсети со мной) или чужой (через роутер)?"

Правило: применить маску к обоим адресам, сравнить сетевую часть.

```
  у меня 10.0.0.5/24,  цель 10.0.0.100

  моя сеть:    10.0.0.0
  сеть цели:   10.0.0.0
                ═══════════
  совпало → СОСЕД → шлю напрямую (ARP → Ethernet-кадр)
```

```
  у меня 10.0.0.5/24,  цель 10.0.5.77

  моя сеть:    10.0.0.0
  сеть цели:   10.0.5.0
                ═══════════
  не совпало → ЧУЖОЙ → шлю через default gateway
```

Без маски это решение принять невозможно. Адреса те же — вердикт разный в зависимости от того, `/24` у тебя или `/16`.

### Маска определяет connected-маршрут

Маска напрямую влияет на то, какой connected-маршрут ядро добавит в [[linux-routing-table|таблицу]]:

```bash
ip addr add 10.0.0.5/24 dev eth0
# → 10.0.0.0/24 dev eth0 proto kernel scope link

ip addr add 10.0.0.5/16 dev eth0
# → 10.0.0.0/16 dev eth0 proto kernel scope link
```

Это **две разные карты мира** для одной и той же машины. В первом случае `10.0.5.77` — чужой (через роутер), во втором — свой (напрямую через ARP).

### Аналогия

- **Адрес** = номер дома (`дом №5`)
- **Маска** = границы района (`Сокольники` / `ЦАО` / `город Москва`)

"Я дом №5" — а в каком районе? От этого зависит, к кому можно дойти пешком, а к кому нужна машина.

### Что ломается при рассинхроне масок

Классический баг: две машины в одном физическом сегменте, но маски разные.

```
  Машина A:  10.0.0.5/24     ← "моя сеть = 10.0.0.0/24"
  Машина B:  10.0.0.100/16   ← "моя сеть = 10.0.0.0/16"
```

- A ↔ B работает (обе считают друг друга соседями)
- Но появляется `10.0.50.1`: A видит как чужого (через роутер), B — как своего (напрямую). **Разное поведение в одной LAN** — типичный источник "пинг проходит, но странно себя ведёт"

Маска — это **контракт** между машиной и её окружением о том, где границы сети. Все хосты в одном сегменте должны иметь согласованную маску, иначе их представления о мире расходятся.

## Типичный порядок команд

Чтобы интерфейс начал работать с IP:

```bash
ip link set eth0 up                    # 1. включить (L1/L2)
ip addr add 192.168.1.10/24 dev eth0   # 2. навесить IP (L3)

# проверить:
ip link show eth0                      # state UP?
ip addr show eth0                      # адрес виден?
ip route show                          # появился connected-маршрут?
```

После этого:
- интерфейс живой
- IP назначен
- ядро **автоматически** добавляет connected-маршрут в [[linux-routing-table|таблицу маршрутов]] (`192.168.1.0/24 dev eth0 proto kernel scope link`)

Работает **одинаково на хосте и на роутере**. Разница только:
- роутер обычно имеет несколько интерфейсов в разных сетях
- включён форвардинг (`sysctl -w net.ipv4.ip_forward=1`)
- в таблице больше маршрутов (static / OSPF / BGP)

## Cheatsheet

```bash
# интерфейсы
ip link show                           # все
ip link show eth0                      # конкретный
ip link set eth0 up                    # включить
ip link set eth0 down                  # выключить
ip link set eth0 mtu 9000              # сменить MTU

# адреса
ip addr show                           # все
ip addr show eth0                      # на конкретном
ip addr add 192.168.1.10/24 dev eth0   # добавить
ip addr del 192.168.1.10/24 dev eth0   # удалить
ip addr flush dev eth0                 # снять все адреса

# старые эквиваленты (устарели, ещё встречаются)
ifconfig eth0 up                       # = ip link set eth0 up
ifconfig eth0 192.168.1.10/24          # = ip addr add + ip link set up
```
