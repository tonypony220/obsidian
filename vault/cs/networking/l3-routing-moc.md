## В чём суть

На **L3** живёт IP. IP даёт **адресацию**: у каждого устройства есть адрес, у каждого пакета есть `src IP` и `dst IP`. Это фундамент.

Но адрес — это **не путь**. Когда пакет приходит на роутер с `dst=10.0.0.5`, роутер должен решить: в какой из своих интерфейсов его отправить и к какому соседу (`next-hop`). Этот выбор и есть **маршрутизация**.

Чтобы решать — у роутера должна быть **таблица маршрутов**: "для префикса `10.0.0.0/24` → next-hop `192.168.1.1` через `eth0`". Вся тема L3-routing — про то, **откуда эта таблица берётся**.

## Проблема

Представь 3 роутера в треугольнике. Чтобы они пересылали трафик, на каждом нужна таблица с маршрутами до сетей за двумя другими. Руками прописать — полминуты.

Теперь представь 100 роутеров. Или 10 тысяч (интернет). Руками — невозможно. А если кабель порвался — все 100 таблиц нужно переписывать.

## Три способа заполнить таблицу маршрутов

1. **Connected** — сети напрямую подключённых интерфейсов. Ядро добавляет само, без конфига.
2. **Static** — `ip route add 10.0.0.0/24 via 192.168.1.1`. Руками. Работает на 2–3 роутерах, не масштабируется.
3. **Dynamic** — **протоколы маршрутизации**. Роутеры сами обмениваются информацией о сетях и строят таблицы. Адаптируются к изменениям топологии.

Суть проекта BADASS — освоить **динамические протоколы**.

## Динамические протоколы

Делятся по области действия:

- **IGP** (Interior Gateway Protocol) — внутри одной организации (AS)
  - OSPF, IS-IS — link-state (каждый знает всю карту)
  - RIP — distance-vector (устарел)
- **EGP** (Exterior Gateway Protocol) — между организациями
  - BGP — единственный используемый сегодня
