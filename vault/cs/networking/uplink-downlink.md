# Uplink vs Downlink

moc: [[networking-moc]]
next:
- [[l2-vs-l3]]
- [[overlay-underlay]]

---

```
                  INTERNET / CORE / SPINE
                          │
                          │  ↑ uplink  (к "верху" иерархии)
                          ▼
                    ┌──────────┐
                    │  device  │
                    └──────────┘
                          │
                          │  ↓ downlink (к "низу" иерархии)
                          ▼
                     HOSTS / LEAF / CLIENTS
```

**TL;DR:** uplink / downlink — **относительные** термины роли порта в иерархии, а не свойство интерфейса. Uplink смотрит к более высокому уровню (к core, к провайдеру, к магистрали), downlink — к более низкому (к клиентам, к хостам). Один и тот же физический порт может быть uplink'ом на одном устройстве и downlink'ом на другом.

## Это роли, не типы портов

Нет технического отличия между «uplink-портом» и «downlink-портом» — это **топологическая роль**, зависит от того, что за ним стоит. Тот же gigabit-Ethernet может быть uplink'ом к провайдеру или downlink'ом к серверу. Разница только в комментарии в конфиге и в договорённости о топологии.

Иногда «uplink» маркируют физически — другим цветом, надписью на свитче — но это конвенция оператора, не спецификация.

## В ДЦ — leaf-spine

В современных fabric-топологиях уплинк/даунлинк приобретают более строгий смысл:

```
      SPINE 1        SPINE 2         ← верхний уровень
       │  │           │  │
       │  └─uplinks───┘  │
       │                 │
      LEAF 1 ─── uplinks ─── LEAF 2  ← leaf-свитчи
       │                     │
      downlinks             downlinks
       │                     │
      серверы               серверы
```

- **Leaf → spine** — это uplink'и (обычно много, для ECMP)
- **Leaf → серверы** — это downlink'и
- На spine downlink'и идут к leaf'ам, uplink'ов часто нет (он и есть «верх»)

## Нюанс: в плоской точка-точка терминология условная

Если два устройства соединены симметрично (например, два роутера через свитч в one-tier топологии), назвать одну сторону uplink'ом — договорённость, не факт. В [[vxlan]]-сценариях часто используют «uplink» для underlay-интерфейса и «downlink» для overlay/host-facing, даже если строгой иерархии нет.

Хороший триггер задать себе вопрос: **есть ли реально «верх» и «низ»?** Если нет — термины применимы условно, не ищи технических отличий.

## Происхождение

Из телекома: **uplink** = канал от наземной станции **к спутнику**, **downlink** = от спутника **к земле**. Оттуда перекочевало в сотовую связь (телефон↔базовая станция), затем в проводные сети как обозначение «ближе к магистрали / дальше от магистрали».

## Не только в сетях

Паттерн «направление относительно иерархии» встречается везде, где есть родитель–ребёнок:

- **Git**: `upstream` (откуда пулим, чаще main-репо) / `downstream` (форки, дистрибутивы). Прямо те же слова.
- **Data pipelines / streaming**: `upstream` (producer) / `downstream` (consumer). «Сломалось upstream» = «сломалось у источника».
- **Процессы Unix**: parent / child — та же иерархия, другие слова.
- **Файловые системы, деревья**: root / leaf, ancestor / descendant.
- **Классы / наследование**: superclass / subclass.

Общее везде: **«направление» имеет смысл только в иерархии, и термины относительные** — одна и та же сущность может быть upstream для одного и downstream для другого.
