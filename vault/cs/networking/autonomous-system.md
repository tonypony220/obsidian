```
   └────────┬───────┘           └─────────┬────────┘
            │                             │
           BGP                           BGP
            │                             │
            ▼                             ▼
   ┌─── AS 3356 ────────────────────────────────────┐
   │  Lumen/Level3 (транзитный провайдер)           │
   └────────────────────────────────────────────────┘
```

**Autonomous System (AS)** — набор IP-сетей и роутеров, управляемый **одной организацией** с **единой политикой маршрутизации**. Базовая единица интернета: интернет — это не плоская сеть миллионов роутеров, а **граф автономных систем**, связанных между собой.

## Зачем придумали

Интернет слишком большой чтобы каждый роутер знал каждый другой. На февраль 2026 в BGP-таблице ~1 миллион префиксов, ~75 тысяч активных AS. Если бы все роутеры пытались знать всё про всех:
- таблицы распухли бы на порядки
- сходимость при изменениях заняла бы минуты-часы
- нужно было бы договариваться о политиках с каждым

Решение — **иерархия через границы AS**:
- **Внутри AS** — свои правила, один язык, полная топология известна. Крутится IGP (OSPF, IS-IS).
- **Между AS** — обмениваются **только достижимостью префиксов** и политикой. Крутится BGP.

AS **инкапсулирует внутреннюю сложность**: соседней AS неважно как у тебя внутри 500 роутеров. Важно только "через тебя можно дойти до таких-то префиксов, какой у тебя AS-path".

## Что входит в AS

- Набор **IP-префиксов**, которые принадлежат этой организации (анонсятся в BGP)
- Набор **роутеров**, реализующих маршрутизацию
- **Согласованная политика** — правила обмена с соседями (кого предпочесть, что анонсировать, что блокировать)
- **Единое управление** — технически одна команда админов, одна инфраструктура

Примеры размеров (на порядок):

| Размер | Префиксов | Пример |
|---|---|---|
| Крошечная | 1 (`/24`) | стартап с серверной |
| Маленькая | 1–5 | региональный провайдер |
| Средняя | 10–100 | крупная компания с офисами по миру |
| Большая | 100–1000 | Google (~500 префиксов под AS 15169) |
| Огромная | 1000+ | Cloudflare (~1500 префиксов под AS 13335) |

## ASN ≠ IP-префиксы — это разные сущности

Частая путаница. Разберём явно:

```
   ┌─── AS 13335 ──── ASN (просто число)
   │
   │   префикс 1.1.1.0/24
   │   префикс 1.0.0.0/24       ← отдельные сущности
   │   префикс 104.16.0.0/12    ← IP-диапазоны, выданные RIR отдельно
   │   ...
   │   (всего ~1500 префиксов)
   │
   │   политика: "анонсирую X провайдеру A, Y не анонсирую"
   │   политика: "от провайдера B предпочитаю через AS-path короче"
   │   ...
   │
   └── роутеры, реализующие это всё
```

**ASN сам по себе ничего не хранит.** Это просто идентификатор "я — вот эта организация" в BGP-сообщениях. Как номер паспорта — сам по себе не имущество, это способ тебя опознать.

**BGP-таблица с префиксами** — живёт **в роутерах** (в [[rib-vs-fib|RIB BGP-процесса]]). Там лежат записи вида "префикс `X` → AS-path `[AS1, AS2, AS3]`". Это уже не про "свой ASN", а про то, что роутер узнал от соседей.

### AS анонсирует свои префиксы в BGP

Когда AS хочет чтобы мир знал "до этих IP можно добраться через меня" — она шлёт BGP UPDATE:

```
  AS 13335 (Cloudflare) ──▶ сосед
  UPDATE:
    prefix: 1.1.1.0/24
    AS-path: [13335]       ← "я, Cloudflare, хозяин этого префикса"
    next-hop: <мой IP>
```

Сосед принимает, добавляет себя в AS-path, передаёт дальше:

```
  AS 3356 (Level3) ──▶ следующий сосед
  UPDATE:
    prefix: 1.1.1.0/24
    AS-path: [3356, 13335]    ← "я могу передать, за мной Cloudflare"
```

Так через несколько хопов весь интернет узнаёт "1.1.1.0/24 лежит за AS 13335". **ASN — это про идентификацию в таких сообщениях, не про хранение префиксов.**

## Нужен ли ASN чтобы получить IP

**Нет.** Это два разных процесса в RIR:

| | IP-префикс | ASN |
|---|---|---|
| Что это | диапазон адресов | идентификатор в BGP |
| Выдаёт | RIR | RIR |
| Нужны оба? | необязательно | необязательно |

### Когда хватает только IP

**Большинство случаев.** Берёшь IP у своего провайдера (так называемые **PA — Provider Aggregatable**), провайдер сам анонсит их под **своим** ASN. Ты не участвуешь в BGP.

Примеры:
- домашний юзер получил `192.0.2.100` от провайдера — никакого ASN у него нет
- небольшой бизнес с одним uplink-ом — то же самое, IP от провайдера, ASN не нужен
- даже крупная компания, если у неё **один** провайдер — может обойтись без своего ASN

### Когда нужен свой ASN

Когда хочешь **независимость от провайдера** в маршрутизации. Основной сценарий — **multi-homing**:

```
   ┌── ISP A ──┐         ┌── ISP B ──┐
   │           │         │           │
   └─────┬─────┘         └─────┬─────┘
         │                     │
         └──────── AS 65099 ───┘
                  (твоя сеть)
                  
          анонсит свои PI-префиксы в обе стороны
          → если ISP A упал, трафик идёт через ISP B
          → BGP сам переключит
```

Для этого нужно:
1. **Свой ASN** — чтобы говорить с обоими ISP по eBGP
2. **PI-префиксы** (Provider Independent) — те, что не зависят от одного провайдера
3. **Свои BGP-роутеры**

Так работают дата-центры, крупные компании, все облачные провайдеры (AWS, GCP — имеют свои ASN и свои префиксы).

### Итог — когда что брать у RIR

- **Только IP (PA)** — если один uplink, простая сеть. 90% случаев.
- **IP + ASN** — если нужен multi-homing или хочешь быть независимым оператором.

Получение публичного ASN — отдельная процедура: заявка в RIR, членский взнос, обоснование необходимости (обычно просят показать что у тебя уже есть multi-homed сеть). Выдают навсегда.

## AS Number (ASN)

Идентификатор AS — число:

- **16-bit** (1–65535) — исторически. В начале интернета казалось "хватит всем".
- **32-bit** (до ~4.3 млрд) — современный стандарт из-за исчерпания 16-bit.
- **Private range:**
  - 16-bit: **64512–65534**
  - 32-bit: **4200000000–4294967294**
  - Используются в лабах, корпоративных сетях, не выпускаются в интернет.

Примеры реальных ASN (можно загуглить):

| ASN | Организация |
|---|---|
| 7 | DoD Network Information Center (первые ASN исторические) |
| 13335 | Cloudflare |
| 15169 | Google |
| 32934 | Facebook/Meta |
| 16509 | Amazon |
| 8075 | Microsoft |
| 3356 | Lumen/Level3 (один из крупнейших транзитных) |

## Кто выдаёт ASN

Как и IP-адреса — **RIR'ы** (Regional Internet Registries). Пять штук по регионам:

- **RIPE NCC** — Европа, Ближний Восток, часть Центральной Азии
- **ARIN** — Северная Америка
- **APNIC** — Азия, Тихоокеания
- **LACNIC** — Латинская Америка
- **AFRINIC** — Африка

Чтобы получить публичный ASN, организация подаёт заявку, платит членский взнос, доказывает что у неё есть multi-homed сеть (подключена к двум провайдерам и хочет делать independent routing). Если условия выполнены — получает ASN навсегда.

## Внутри vs между AS

Ключевое разделение, которое определяет всю дальнейшую структуру:

```
  ┌─────────── AS 65001 ────────────┐
  │                                 │
  │   R1 ─── OSPF ─── R2 ─── R3     │   ← IGP внутри
  │   │                        │    │     (как быстрее)
  │   │                        │    │
  │   │                        │    │
  │   iBGP ────────────────── iBGP  │   ← iBGP согласует
  │   │                        │    │     внешние маршруты
  └───┼────────────────────────┼────┘
      │                        │
     eBGP                      eBGP             ← EGP между AS
      │                        │                  (как политически)
      ▼                        ▼
  ┌─── AS 65002 ────┐   ┌─── AS 65003 ────┐
  │                 │   │                 │
  └─────────────────┘   └─────────────────┘
```

- **IGP** (OSPF, IS-IS) — внутри AS: минимизируем латентность, считаем cost, все роутеры "свои".
- **eBGP** (external BGP) — между разными AS: обмениваемся префиксами и политиками.
- **iBGP** (internal BGP) — внутри AS, но не для IGP-маршрутов, а для **согласования внешних маршрутов**: если `R1` узнал что-то по eBGP от соседней AS, он должен это рассказать `R3`, чтобы `R3` тоже мог форвардить в ту сторону.

Это самая частая путаница: **iBGP — не IGP**. Это BGP в режиме "сосед в моей AS", нужен чтобы раздавать внешние знания внутри своей сети. IGP и iBGP решают разные задачи и работают параллельно.

## Peering vs Transit — отношения между AS

Две базовых бизнес-модели того, как AS подключаются друг к другу.

### Transit (платный)

Маленькая AS платит большой за **выход в интернет**. Большая анонсит ей весь интернет, маленькая анонсит большой свои префиксы. Большая передаёт маленькую дальше.

```
   AS Little ─── $$ ─── AS Big ─── рестинтернет
```

### Peering (бесплатный)

Две AS сопоставимого размера обмениваются **только своими префиксами**. Не передают чужой трафик дальше. Обычно бесплатно, потому что выгодно обеим.

```
   AS Cloudflare ══ peering ══ AS Google
   (оба видят трафик друг к другу напрямую, минуя транзит)
```

**Tier 1** — AS, которые ни за что не платят. Только peering с другими Tier 1. Примеры: Level3, NTT, Telia, Deutsche Telekom, Tata. Их около 15. Они формируют **хребет интернета**.

**Tier 2** — покупают transit у Tier 1, но сами активно peer'ятся с другими.

**Tier 3** — только transit, маленькие локальные провайдеры.

Именно эти отношения кодируются в **BGP-политике**: "этому соседу анонсирую всё, этому только свои префиксы, этого предпочитаю по AS-path length". Отсюда фраза "BGP — это политика, а не поиск кратчайшего пути".

## В BADASS

В P3 каждый роутер или группа роутеров — своя AS (или все в одной AS, зависит от топологии). ASN берутся из **private range** (`65xxx`). BGP-сессии между ними несут **EVPN-маршруты** — не классические IP-префиксы, а MAC-адреса хостов за VXLAN-фабрикой.

Это нестандартное использование BGP: не "маршруты в интернет", а **control plane для L2-оверлея**. Но концепция AS и разделения "внутри / между" остаётся та же.
