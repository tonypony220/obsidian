```
ДО — pin опционален                 ПОСЛЕ — pin структурен

schema = z.object({...})            schema = pinned<T>()(
pin    = type-assert                  z.object({...})
          ▲                         )
   отдельная декларация                       ▲
   рядом со схемой                  единственный путь экспорта
          │                                   │
   "забыл написать" — валидно       "забыл" = "не вызвал pinned"
          │                                   │
   нужен внешний guard              guard невозможен по построению
   (lint / AST-walker /             — состояние "схема без pin'а"
    grep)                              не имеет представимого типа
```

**TL;DR:** обязательная ручная декларация → silent gap. Переносим её внутрь конструктора результата → состояние «забыл» становится синтаксически невыразимым, внешний guard не нужен.

## Механизм

- Инвариант X должен сопровождать каждое значение типа Y
- Наивно: «правило» — X пишется рядом с Y; компилятор молчит, если X забыт → нужен detection-механизм (guard, тест, lint), который проверяет наличие X постфактум
- Pin by construction: единственный способ получить Y — пройти через конструктор `make(...)`, в типе которого X уже зашит. Если X отсутствует/не сходится — `make(...)` не типизируется, Y не существует
- Detection превращается в **constructive impossibility**: нечего детектировать, потому что нарушающее состояние не выражается типами

## Сдвиг инварианта влево

Это конкретный случай главного правила из [[architecture-stack]]: инвариант поднимается на самый левый слой, который способен его удержать.

| Где жил инвариант | Чем ловится | Цена ошибки |
|---|---|---|
| Процесс (review «проверь, что pin есть») | человек | высокая, late |
| Верификация (guard-тест / AST-walker) | CI | средняя, после написания |
| **Контракт (тип конструктора)** | **компилятор** | **noль, на месте** |

Каждый шаг влево: ×10 дешевле обнаружение, ×N меньше способов забыть. Колонка enforcement из [[architecture-stack]]: external lock (guard) → built-in lock (тип результата).

## Связь с Make Illegal States Unrepresentable

[[type-driven-design]] обычно применяет MISR к **данным** — варианты `Loading | Success | Error` вместо boolean-flag tangle. Pin by construction — то же самое, применённое к **конвенции кодовой базы**: состояние «схема экспортирована, pin не написан» не имеет представимого типа.

Родственно [[parse-dont-validate]]: вместо «провалидируй на входе и потом доверяй» — «получи значение только через парсер, типы дальше гарантируют». Та же идея: invariant by construction, а не by inspection.

## Trade-off — единственный

- **Что меняется:** silent risk → loud chore. «Забыл pin» больше не молчит в течение недель — оно либо компилится (значит pin есть), либо нет (значит сразу видно)
- **Что НЕ меняется:** если инвариант требует дублирования (как поля схема↔тип), pin by construction не убирает дубль — он только превращает drift между копиями в громкий fail. Дубль остаётся, но он перестаёт быть тихим
- Невыгодно только если базовая боль уже loud — тогда добавляем церемонию без выигрыша

## Когда применять

Сигналы что задача — про pin by construction:
- В кодревью/треде звучит «надо заставить не забыть написать X»
- Появляется идея guard-теста / lint-правила / AST-walker'а, который проверяет наличие декларации
- Naming-хаос вокруг этой декларации (`_pinFoo`, `_AssertFoo`, `_check_foo`) — признак, что её все пишут немного по-разному, и grep не работает

Reframe-вопрос: **почему этот шаг вообще можно забыть?** Если ответ — «потому что он структурно опционален» → переноси шаг в конструктор результата, а не строй detection.

## Не только в TypeScript

- **Rust typestate** — состояние объекта закодировано в типе (`File<Open>` vs `File<Closed>`). Метод `.read()` существует только на `File<Open>`. «Забыл открыть» = не компилируется.
- **Builder с обязательными полями** — `.build()` объявлен только на типе, где все обязательные `.withX()` уже вызваны (через phantom type-параметры). «Забыл required-поле» = `.build()` не существует.
- **Sealed constructor + factory** — конструктор приватный, единственный путь создать значение — через factory, которая делает валидацию. Невалидный инстанс не имеет способа возникнуть.
- **Типизированные middleware-цепочки** — handler требует параметр `Request<Authenticated>`. Auth middleware — единственное, что возвращает этот тип. «Забыл подключить auth» = handler не вызывается, цепочка не собирается.

Общее везде: **обязательный шаг закодирован в типе результата, а не в инструкции «не забудь сделать X»**. Detection требует, чтобы нарушение существовало и было найдено; construction делает нарушение несуществующим.
