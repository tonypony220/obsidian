Слой верификации: тест = **детектор поломки**. Вопрос к любому тесту: «какую правку кода он поймает?». Ветка наращивается по мере разборов; серая ссылка = ещё не разобрано.

## Карта: где какой тест режет

```
                UI   hook  build   ┃HTTP┃  schema  route  domain   ext

unit                                                       ■              pure fn, без фреймворка
round-trip                                  ■                             canonical type ↔ wire-schema, offline
RTL wiring       ■════■═════■      mock                                   click → builder вызван с X (мок сеть)
character-                         mock     ■══════■══════■        mock   реальный route+domain, мок внешнего IO
ization
walking sk.      ■════■═════■══════HTTP═════■══════■══════■        mock   тончайший полный срез через все слои
e2e              ■════■═════■══════HTTP═════■══════■══════■         ■     реальное всё (staging)

fitness          статический анализ репо (grep/AST)                       структурный инвариант репо
coverage-        анти-паттерн, не тип теста                               тест зелён, целевой класс бага не ловится
theatre
```

Как читать:
- **колонки** = слои пайплайна, от кнопки до внешнего IO
- **строки** = классы тестов
- `■═══■` = реально прогоняется в тесте
- `mock` = граница где IO подменяется
- пусто = вне зоны теста

Два принципа:
- **Вертикально:** ниже строка → больше слоёв реально прогоняется → дороже поймать регрессию. Верх = дёшево и локально; низ = дорого и системно
- **Горизонтально:** `┃HTTP┃` — водораздел клиент/сервер. Слева живёт код браузера/RN, справа — код сервера; walking skeleton и e2e — единственные, кто пересекает границу

Ортогонально карте: [[baseline-positive-boundary-reject]] — дисциплина ЧТО кладётся внутрь ячейки (positive — через реальный builder; negative — рукописный мусор), не отдельная строка. [[coverage-matrix]] — тот же материал повёрнут: «flows × layers» вместо «tests × layers», показывает где на карте дыра.

## Структура цепочки

- [[walking-skeleton]] — тончайшая цепочка через реальные слои: builder → route → handler; мок только на IO-границе
- [[rtl-wiring-test]] — тот же принцип в UI: «click → builder вызван с X»; мокается сеть, не builder
- [[round-trip-test]] — output реального builder'а × schema.parse; runtime-родственник типовых пинов

## Источник истины

- [[baseline-positive-boundary-reject]] — пара: happy-path никогда не пишет body руками / рукописный мусор легитимен только в negative
- [[coverage-theatre]] — анти-паттерн: мок глушит проверяемое; тест, срисованный с кода, пинует его баг и остаётся зелёным

## Покрытие и инварианты

- [[coverage-matrix]] — таблица flows × layers: видно, какой слой какого flow пуст
- [[fitness-function]] — структурный инвариант репо как тест (single-producer, контракт cron-роутов)
- [[characterization-test]] — зафиксировать текущее поведение перед рефактором
