# Overlay vs Underlay

---

```
  ┌───────────────────────────────────────────────┐
  │  OVERLAY (виртуальная сеть)                   │
  │                                               │
  │   A ─────────── ARP / BUM ────────── B        │
  │   (видят друг друга в одном L2-сегменте)      │
  │                                               │
  └──────────┬────────────────────┬───────────────┘
             │                    │
         VTEP-A               VTEP-B         ← "клей" (encap/decap)
             │                    │
  ┌──────────▼────────────────────▼───────────────┐
  │  UNDERLAY (реальная L3-сеть)                  │
  │                                               │
  │   192.168.1.5 ── R ── R ── 192.168.1.6        │
  │   (OSPF/BGP/static — обычная IP-маршрутизация)│
  │                                               │
  └───────────────────────────────────────────────┘
```

**TL;DR:** Overlay — виртуальная сеть, построенная **поверх** другой. Underlay — физическая/логическая сеть, которая её несёт. Классический пример: [[vxlan|VXLAN]] — L2-overlay поверх L3-underlay. Каждый слой работает **независимо**: underlay ничего не знает про overlay, overlay не видит топологию underlay.

## Разделение ответственности

| | Underlay | Overlay |
|---|---|---|
| Что это | реальная сеть (железо + L3-маршрутизация) | виртуальные сегменты, собранные программно |
| Адреса | реальные IP хостов/VTEP'ов | MAC/IP внутри виртуального сегмента |
| Протоколы | OSPF, BGP, static routes | ARP, DHCP, broadcast — как в обычной LAN |
| Видит ли нижний слой | — | underlay-IP своего VTEP'а + IP удалённых VTEP'ов |
| Видит ли верхний слой | нет (для underlay overlay-трафик — обычные UDP-пакеты) | — |

Underlay и overlay — **разные IP-сети с разными адресными пространствами**. IP `10.0.0.20` в overlay не имеет никакого отношения к IP `192.168.1.5` в underlay.

## Что делает VTEP (tunnel endpoint)

VTEP (VXLAN Tunnel Endpoint) или любой другой tunnel endpoint — **граница между слоями**:

- **Encap**: берёт кадр/пакет из overlay, заворачивает в пакет underlay (добавляет outer-заголовок с underlay-адресами), отдаёт в underlay.
- **Decap**: получает пакет из underlay, снимает outer-заголовок, отдаёт оригинал в overlay.

У VTEP всегда **два контекста**: адрес в underlay (по которому к нему адресуются другие VTEP'ы) и участие в overlay-сегментах (VNI/VLAN/туннелях).

## Почему разделение полезно

1. **Масштаб** — underlay можно сделать маршрутизируемой L3-фабрикой (Spine-Leaf) с миллионами маршрутов. Overlay даёт приложениям нужную L2-семантику поверх.
2. **Независимость** — можно менять underlay (перепрокладывать кабели, менять BGP-политики) не трогая приложения. И наоборот — создавать/удалять overlay-сегменты не трогая underlay.
3. **Multi-tenancy** — один underlay обслуживает тысячи изолированных overlay'ев (один VNI = один тенант в [[vxlan|VXLAN]]).
4. **Мобильность** — VM переезжает между хостами, меняется только VTEP; underlay ничего не замечает, overlay семантика сохраняется.

## Не только VXLAN

Паттерн overlay/underlay шире, чем VXLAN:

- **VPN** (IPsec, WireGuard, OpenVPN) — L3-overlay поверх L3-underlay (интернет)
- **GRE, Geneve, VXLAN** — L2/L3 overlay'и с разными заголовками
- **MPLS L2VPN/L3VPN** — overlay поверх MPLS-underlay
- **Kubernetes CNI** (Flannel, Calico, Cilium) — overlay сеть подов поверх underlay хостов

Везде одна и та же логика: encap в граничной точке, decap на другой стороне, независимость слоёв.

## Главное следствие — вопрос «куда слать»

В обычной сети (без overlay) ответ на вопрос «куда слать broadcast?» даёт сама физика: broadcast-домен = провода, идущие до одного свитча. Всё что воткнуто — в домене.

В overlay физики нет — **нужен явный механизм**, говорящий какие VTEP'ы состоят в одном сегменте. Варианты (подробно — [[vxlan-modes]]):

- **Static** — админ прописал
- **Multicast** — VNI привязан к underlay-multicast группе
- **Control plane (EVPN)** — BGP разносит информацию «какой MAC за каким VTEP»

Это и есть **единственное что overlay добавляет к обычной L2-логике**: способ узнать членов сегмента, раз физического broadcast-домена больше нет.
