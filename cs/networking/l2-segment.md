# L2 Segment

moc: [[networking-moc]]
back: [[l2-vs-l3]]
next: [[arp]] [[bum-traffic]] [[linux-bridge]] [[vlan]] [[vxlan]] [[vni]]

---

```
    ┌─────────── L2-сегмент (= broadcast-домен) ──────────┐
    │                                                     │
    │   A ───┐                                            │
    │   B ───┼── [switch] ── [switch] ── C                │
    │   D ───┘                           │                │
    │                                    E                │
    │                                                     │
    │   ARP/broadcast от A достигает: B, C, D, E          │
    └────────────────────┬────────────────────────────────┘
                         │
                     [ router ]        ← L3-граница, сегмент кончается
                         │
    ┌────────────────────▼───── другой L2-сегмент ────────┐
    │   F ── [switch] ── G                                │
    │   broadcast F ↔ G — не долетает до A/B/C/D/E        │
    └─────────────────────────────────────────────────────┘
```

**TL;DR:** L2-сегмент — множество сетевых интерфейсов, между которыми **L2-broadcast проходит без преобразования**. Эквивалентное определение: область, где работает [[arp|ARP]] и flood-and-learn. Границы сегмента — **роутеры** (L3-устройства). Свитчи и [[linux-bridge|bridge]]'и — **не** границы, они прозрачны для L2.

## Три эквивалентных определения

Одна и та же сущность описывается несколькими способами — полезно держать все три в голове:

1. **Broadcast-домен** — множество интерфейсов, до которых долетит кадр с `dst MAC = ff:ff:ff:ff:ff:ff`.
2. **ARP-домен** — область, где [[arp|ARP]]-запрос находит получателя (broadcast ограничен той же областью).
3. **Flood-домен** — область, на которую свитчи флудят unknown unicast и [[bum-traffic|BUM]].

Все три описывают **одно и то же** множество интерфейсов. Если ARP доходит — значит broadcast доходит — значит флуд доходит.

## Что не является границей сегмента

- **Свитч** (физический или [[linux-bridge|виртуальный]]) — прозрачный для L2. Он форвардит кадры, не преобразует их. Два свитча, соединённые кабелем = один сегмент.
- **Hub** — тоже прозрачный.
- **Кабель** — тем более.
- **[[veth-pair|veth]]** — L2-труба, не граница.

Добавление свитчей в сегмент **не создаёт** новые сегменты — просто увеличивает физический размер одного сегмента.

## Что является границей

- **Роутер** — L3-устройство. Снимает L2-заголовок, смотрит IP, надевает новый L2-заголовок (см. [[l2-vs-l3]]). На каждой «ноге» роутера — свой L2-сегмент.
- **[[vlan|VLAN]]-теги** — внутри одного физического свитча создают **несколько независимых** сегментов. Порт в VLAN 10 и порт в VLAN 20 физически соединены через чип свитча, но L2 между ними не ходит.
- **Граница VXLAN VNI** — разные VNI = разные сегменты, даже на одном VTEP.

## Что общего у «обычного», VLAN и VXLAN сегментов

Сегмент не обязан быть физическим — он определён **поведением broadcast**, а не проводами:

| Реализация | Что определяет сегмент |
|---|---|
| Классический Ethernet | один свитч / цепочка свитчей |
| [[vlan|VLAN]] | порты с одинаковым VLAN ID |
| [[vxlan|VXLAN]] | интерфейсы в одном VNI (даже на разных физ. хостах через [[overlay-underlay|underlay]]) |
| [[linux-bridge]] | интерфейсы, добавленные через `ip link set … master br0` |

Внутри любого из них: [[arp|ARP]] работает одинаково, MAC-learning одинаковый, broadcast одинаковый. Приложения **не различают** — для них это просто L2-сегмент.

## Сегмент ≠ IP-подсеть

Концептуально это разные вещи:

- **L2-сегмент** — свойство L2 (кому долетает broadcast)
- **IP-подсеть** — свойство L3 (какой диапазон IP считается «соседями»)

Админ обычно **выравнивает** их один-к-одному (один VLAN = одна подсеть `10.0.10.0/24`) — так удобнее. Но технически в одном L2-сегменте можно держать несколько подсетей, и наоборот (редко и обычно ошибка конфигурации).

## Почему размер сегмента ограничивают

Все члены сегмента получают весь BUM-трафик. Чем больше хостов — тем больше ARP-шума, broadcast storm-рисков, нагрузки на NIC. Современные ДЦ делают underlay **полностью L3** (каждый хост в своём маленьком L2), а общие L2-сегменты строят через overlay ([[vxlan|VXLAN]]) с контролируемым размером по VNI.
