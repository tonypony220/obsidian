# LLM vs эмбеддинги для классификации

moc: [[ml-moc]]
next: [[centroid]] [[logistic-regression]]

---

```
текст ──┬── Embedding ──► вектор [768] ──► LogReg ──► класс
        │    (быстро, дёшево, грубо)
        │
        └── LLM ──────────────────────────────────► класс
             (медленно, дорого, точно)

стратегия: Embedding → отсечь мусор → LLM → точная классификация
```

**Эмбеддинг** сжимает текст в вектор фиксированного размера (768 чисел), отражающий общий смысл. Не знает задачу — сжимает одинаково для любого use case. Нюансы теряются при сжатии.

**LLM** читает текст целиком и рассуждает в контексте инструкции. Понимает задачу, применяет логику, учитывает контекст.

|             | Эмбеддинг         | LLM                |
|-------------|--------------------|--------------------|
| Стоимость   | Почти бесплатно    | Дорого (токены)    |
| Скорость    | Быстро (батчами)   | Медленно           |
| Качество    | Грубое разделение  | Точное решение     |

Оптимальная стратегия — двухступенчатая: эмбеддинг как быстрый грубый фильтр (отсечь очевидный мусор), LLM для точной классификации оставшегося.
