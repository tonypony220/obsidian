# IVF — кластерный индекс для поиска соседей

moc: [[ml-moc]]
next:
- [[hnsw-index]]
- [[centroid]]
- [[recall]]

---

```text
обучение:  выборка ──k-means──► C1, C2, ... Ck
                                      │
добавление: vector ──nearest C────────┤
                                      ▼
                 C1 → [v2, v8, ...]   C2 → [v1, v7, ...]

запрос: query → ближайшие nprobe центроидов → их списки → top-k
```

**TL;DR:** IVF явно делит векторное пространство на области вокруг центроидов и ищет только в нескольких соответствующих списках. Поиск масштабируется, потому что не сканирует всю коллекцию; обучение и обслуживание нужны для сохранения удачного разбиения.

## Построение: обучение индекса

На репрезентативной выборке векторов запускается `k-means`, который находит `nlist` [[centroid|центроидов]]. Затем каждый вектор назначается ближайшему центроиду:

```text
list(v) = argminᵢ distance(v, Cᵢ)
```

Так возникают inverted lists — списки идентификаторов векторов для каждой области. Обучение здесь означает кластеризацию без разметки, а не обучение embedding-модели. В `IVF+PQ` дополнительно обучаются кодовые книги сжатия.

## Поиск

Для запроса `q`:

1. Найти ближайшие `nprobe` центроидов.
2. Прочитать только соответствующие inverted lists.
3. Сравнить `q` с их векторами или PQ-кодами.
4. Вернуть `top-k` ближайших кандидатов.

```text
nprobe ↓ → меньше работы, ниже recall
nprobe ↑ → больше работы, выше recall
```

Результат приближённый: истинный сосед может оказаться по другую сторону границы области, список которой не был выбран.

## Почему поиск масштабируется

При равномерных списках один список содержит примерно `N / nlist` векторов. Число проверяемых кандидатов:

```text
candidates ≈ nprobe × N / nlist

N = 1 000 000, nlist = 1 000, nprobe = 3
→ около 3 000 кандидатов вместо 1 000 000
```

`IVF+PQ` дополнительно уменьшает память: вместо исходных float-векторов при поиске используются компактные коды. Поэтому IVF подходит для больших коллекций, batch-поиска, GPU и распределённого хранения.

## Добавление и обслуживание

После обучения новый вектор не запускает `k-means` заново: достаточно найти ближайший фиксированный центроид и дописать вектор в его список. Но центроиды сами не перемещаются вслед за новыми данными.

| Изменение данных | Последствие | Обслуживание |
|---|---|---|
| вырос объём | списки стали длиннее | увеличить `nlist`, перестроить индекс |
| изменилось распределение | часть списков перегружена | переобучить центроиды на актуальной выборке |
| накопились удаления | лишние чтения и память | уплотнить или перестроить индекс |
| изменились эмбеддинги | старое разбиение больше не соответствует векторам | пересчитать векторы и индекс |

Масштабируемость описывает стоимость запросов в уже построенном индексе. Обучение и обслуживание описывают его жизненный цикл; это разные свойства.

## IVF и HNSW

IVF создаёт явные области через центроиды и `cluster_id`. [[hnsw-index|HNSW]] кластеров не создаёт: он соединяет близкие вершины рёбрами. FAISS — библиотека, которая поддерживает оба типа индекса, а не альтернатива HNSW.
