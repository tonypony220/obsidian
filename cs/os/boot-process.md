```
power ─▶ BIOS/UEFI ─▶ bootloader (GRUB) ─▶ kernel
         ROM, POST,    умеет ФС: находит     _start → kmain()
         ищет boot-    файл ядра, парсит
         устройство    ELF, грузит в RAM,
                       ставит режим CPU,
                       jmp на entry point
```

**TL;DR:** после включения прошивка загружает загрузчик, загрузчик кладёт ядро в память, приводит CPU в известное состояние и прыгает на entry point — дальше машина полностью твоя.

## Кто где живёт и кто кого туда положил

| Программа | Что это | Где лежит | Кто положил |
|---|---|---|---|
| Прошивка (BIOS/UEFI) | код в чипе на материнке | ROM-чип платы | производитель платы |
| Загрузчик (GRUB) | обычная программа (чужой готовый код GNU) | диск/ISO, спец-«загрузочное место» | установщик ОС; в KFS — мы, через `grub-mkrescue` |
| Ядро (kernel.bin) | наш код | диск/ISO, обычный файл | мы (Makefile) |

- Пуск цепочки зашит в кремний: после подачи питания CPU всегда берёт первую инструкцию с фиксированного адреса, а тот заведён на ROM-чип прошивки. Прошивку никто не запускает — она исполняется «потому что так устроен процессор».
- `qemu -kernel kernel.bin` пропускает первые два этапа: QEMU сам играет роль прошивки и загрузчика.

## Этапы

- **BIOS/UEFI** — POST (проверка железа), поиск загрузочного устройства, загрузка следующего этапа. Два пути ([[bios-vs-uefi]]): **BIOS файловых систем не знает** — читает сектор №0 по номеру (позиция, не имя — «опустить иглу на край пластинки»), проверяет печать и исполняет эти 512 байт; **UEFI** умеет ровно одну ФС (FAT) и запускает файл по известному пути (`/EFI/BOOT/BOOTX64.EFI`). У CD свой стандарт вместо сектора №0 — [[el-torito]]. Дальше прошивка ничего не умеет — её работа кончилась.
- **Bootloader (GRUB)** — «умный» этап: умеет файловые системы, находит файл ядра, парсит его формат ([[elf-format]]), копирует секции по адресам из [[linker-script]], переключает CPU в [[protected-mode]] и прыгает на entry point. Сам GRUB тоже ступенчатый — целиком в 512 байт не влезает: stage1 в MBR («загрузи соседние секторы по номерам») → core.img с драйверами ФС → полный GRUB, открывающий файлы по именам.
- **Ядро** — получает управление в состоянии, описанном контрактом [[multiboot]]: код загружен в память, но нет ни стека, ни libc — см. [[freestanding-environment]].

## Термины (шпаргалка)

- **ROM** — память, живущая без питания: «впечатано в устройство». RAM — черновик, пустеет при каждом выключении
- **POST** (power-on self-test) — самопроверка железа при включении: чеклист пилота перед вылетом
- **Загрузочное устройство** — роль, не тип железа: любой носитель (диск, флешка, CD, сеть), где прошивка нашла загрузочную запись с меткой `0x55AA` — «печатью на конверте»: содержимое прошивка не понимает, проверяет только печать. Обходит устройства по boot order (меню F12/Del) и грузится с первого совпадения. Наш `kfs.iso` в `qemu -cdrom` — виртуальный CD с такой печатью от grub-mkrescue
- **MBR** — первые 512 байт диска; прошивка исполняет их вслепую: «записка на двери: начинай отсюда»
- **0x7C00** — адрес RAM, куда BIOS копирует загрузочный сектор и прыгает. Историческое число: минимальный IBM PC имел 32 КиБ RAM, 0x7C00 = 32К − 1К — сектор кладут в самый верх, низ свободен под то, что он загрузит. CD-путь ([[el-torito]], load segment 0 = дефолт 0x7C0) приземляется туда же
- **EFI-приложение** — современная замена MBR: прошивка UEFI сама умеет читать FAT-раздел и запускает с него файл-программу `.efi`
- **Файловая система** (ext4, FAT32…) — правила раскладки файлов по секторам: оглавление книги. Без неё диск — просто длинная лента байтов без имён и границ
- **[[elf-format|ELF]]** — формат исполняемого файла: «накладная», по которой загрузчик раскладывает куски файла по памяти
- **Entry point** — адрес первой инструкции ядра, куда прыгает загрузчик (наш `_start`)

## Зачем цепочка, а не сразу ядро

Каждый этап меньше и глупее следующего: MBR — 512 байт, GRUB — сотни КБ, ядро — мегабайты. Прошивка не обязана уметь ext4 и ELF — она умеет ровно столько, чтобы загрузить следующий, более умный этап.

## Концепция шире (staged bootstrap)

- Компиляторы: минимальный компилятор собирает полноценный (bootstrapping)
- Embedded: BootROM → SPL → U-Boot → Linux (U-Boot — «GRUB embedded-мира», SPL — его крошечный предзагрузчик)
- JVM: bootstrap classloader → system classloader → приложение

Общее везде: маленький доверенный этап загружает больший, пока не поднимется целевая система.
