# El Torito — загрузка с CD

back: [[boot-process]]
next:
- [[bios-vs-uefi]]

---

```
kfs.iso (ISO9660 — просто ФС, сама по себе НЕ загрузочная)
│
sector 17 ─▶ Boot Record ─▶ boot catalog (табличка записей):
                            ├─ 0x00 «80x86»  ─▶ eltorito.img        ◀── SeaBIOS
                            │   (GRUB core из модулей i386-pc)
                            └─ 0xEF «EFI»    ─▶ FAT-образ c .efi    ◀── UEFI
```

**TL;DR:** ISO9660 — просто файловая система; загрузочность — отдельная надстройка El Torito: таблица «какой прошивке какой вшитый загрузчик». Прошивка ищет в ней запись **своей** платформы; нет записи — «незагрузочный» диск, даже если файлы целы.

## Механика

1. Прошивка читает **сектор 17** диска — там Boot Record Volume Descriptor: указатель на boot catalog.
2. **Boot catalog** — таблица записей по 32 байта. Ключевое поле — **platform ID**: `0x00` = 80x86 (классический BIOS), `0xEF` = EFI. В записи: LBA вшитого загрузочного образа и сколько секторов грузить.
3. Прошивка идёт не по файлам, а прямо в каталог, и ищет запись своей платформы: SeaBIOS → `0x00`, UEFI → `0xEF`. Нашла → тащит секторы в память, прыгает. Для BIOS это `eltorito.img` GRUB'а (стартер + core.img из модулей `i386-pc`); для UEFI — FAT-образ с `.efi` внутри.

Один диск спокойно несёт **обе** записи — нормальный ISO так и устроен и грузится где угодно. Дальше по цепочке — [[boot-process]]: GRUB читает ISO9660 уже сам, находит ядро, [[multiboot]].

## Ловушка: mkrescue кладёт только то, что нашёл

`grub-mkrescue` наполняет каталог записями тех платформ, чьи GRUB-модули есть на машине **в момент сборки**: нет каталога `i386-pc` (голая UEFI-Fedora) → нет записи `0x00`. Команда та же, exit code 0, файл создан, размер похожий — а BIOS-запись отсутствует.

Симптом (scar KFS 2026-08): QEMU (по умолчанию SeaBIOS — [[bios-vs-uefi]]) листает каталог, записи `0x00` нет → **«Could not read from CDROM (code 0004)»**. Это не «нет диска» — диск есть и читается; нет загрузочной записи для *этой* прошивки.

Посмотреть каталог глазами:

```sh
xorriso -indev kfs.iso -report_el_torito plain
# здоровый образ: строки и для BIOS (0x00), и для EFI (0xEF)
```

## Концепция шире (один артефакт — несколько платформенных payload'ов)

- macOS universal (fat) binaries — один файл, срезы x86_64 + arm64; ядро выбирает свой
- OCI image index (docker manifest list) — один тег, за ним образы под amd64/arm64
- hybrid ISO — тот же диск размечен и как CD, и как GPT-флешка

Общее везде: артефакт несёт таблицу «платформа → payload», а выбор делает исполняющая среда; отсутствие записи под твою платформу выглядит как «битый артефакт», хотя остальные записи целы.
