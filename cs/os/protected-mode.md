# Protected mode

moc: [[os-moc]]
back: [[boot-process]]
next:
- [[multiboot]]

---

```
real mode (16-bit, 1978)   protected mode (32-bit)
─────────────────────────  ─────────────────────────
1 МБ адресов               4 ГБ адресов
segment:offset             сегменты через GDT
нет защиты памяти          + (опционально) paging
                           кольца привилегий 0–3
```

**TL;DR:** protected mode — «нормальный» 32-битный режим x86 с защитой памяти и кольцами привилегий; GRUB переключает CPU в него до передачи управления, поэтому ядро KFS стартует сразу в 32 битах.

## Хронология: кто исполняется в каком режиме

```
кто:    [прошивка]──[GRUB]────────────────╳──[ядро]──▶
                                          ↑ handoff (jmp _start)
режим:  ←── real ──→│←──── protected ────────────────▶
              GRUB переключил ↑
```

Режим — не этап загрузки, а положение переключателя внутри CPU. Правило совместимости Intel: каждый x86 после включения притворяется 8086-м (1978) — поэтому прошивка и MBR-код 16-битные, а ритуал real → protected проходит каждая загрузка. Мы real mode не видим: GRUB прошёл его за нас.

## Зачем знать, если GRUB уже всё сделал

- x86 ради совместимости включается в real mode 1978 года (16 бит, 1 МБ адресов). Каждый загрузчик проходит путь real → protected сам; GRUB избавляет ядро от этой археологии.
- Но «protected mode включён» держится на GDT загрузчика, а [[multiboot]] прямо говорит: полагаться на неё нельзя. Загрузка собственной GDT — первое дело следующих KFS.
- Кольца привилегий: ядро в ring 0 (доступны все инструкции), user-код в ring 3. До процессов далеко, но модель разделения kernel/user space растёт отсюда.

## Что важно для KFS_1

- Регистры 32-битные (`esp`, `eax`), адресация плоская: адрес 0xB8000 значит буквально «байт номер 0xB8000» — см. [[vga-text-mode]].
- Paging выключен: виртуальный адрес = физический. Включение paging — отдельный проект (KFS_3).
