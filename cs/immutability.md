# Иммутабельность

moc: [[fp-patterns-moc]]
next: [[pure-functions]] [[flat-vs-orthogonal-state]]

---

```
мутация:                   иммутабельность:
┌──────────────┐           ┌──────────────┐   ┌──────────────┐
│ user         │           │ user (orig)  │   │ updated      │
│  name: "Bob" │─► "Alice" │  name: "Bob" │   │  name: "Alice│
│  age: 30     │           │  age: 30     │──►│  age: 30     │
└──────────────┘           └──────────────┘   └──────────────┘
   объект сломан              оригинал цел       новый объект
```

Не мутировать данные, а создавать новые. Основа предсказуемого состояния.

```ts
// мутация — ООП-стиль
user.name = "Alice";
items.push(newItem);

// иммутабельность — ФП-стиль
const updated = { ...user, name: "Alice" };
const newItems = [...items, newItem];
```

## Где встречается

React state (setState возвращает новый объект), Redux reducers, Immer, spread-операторы повсюду. В Rust иммутабельность по умолчанию (`let` vs `let mut`).

## Зачем

Мутация — главный источник багов в сложном коде. Если данные не меняются, можно безопасно передавать их куда угодно без копирования и без страха что кто-то их сломает.

## Происхождение

Лямбда-исчисление (1930-е) → в мейнстриме с React/Redux (2015+).
