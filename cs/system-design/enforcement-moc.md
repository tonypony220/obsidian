Сила: правило без механизма = пожелание. Enforcement — не слой, а **замок на каждом слое** стека. Иерархия замков по силе: тип (компилятор) → линтер → CI-гейт → текст для агента / ревью. Правило стремится мигрировать влево по иерархии; текстовый слой — постоянный дом только для правил, невыразимых механикой.

## Типовые замки (компилятор)

- [[branded-types]] — номинальность в структурной системе; техническая основа brand gate
- [[brand-gate]] — `Built<T>`: пропуск выдаёт только канонический builder, транспорт требует; обход не компилируется

## Линтер и CI

- [[fence]] — eslint-запрет raw fetch / запретных импортов вне разрешённых зон
- [[allowlist-ratchet]] — legacy в явный список; список может только уменьшаться
- [[fix-on-touch]] — grandfathering: старое не блокирует мердж, чинится при касании файла
- [[fitness-function]] — структурный инвариант репо как CI-тест

## Агентный слой (механикой не выразимо)

- [[hard-gate-silent-nack]] — блокирующие правила в CLAUDE.md / AGENTS.md: gate = протокол «прочитай скилл до кода; конфликт → эскалация оператору», NACK = таблица «❌ форма → ✅ канон», применяется без обсуждения
- [[anchor-questions]] — чеклист перед diff: «нет» хоть на один → чинить до мерджа
