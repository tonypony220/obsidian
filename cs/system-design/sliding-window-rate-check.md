# Sliding window rate check

---

```
K=3, W=10: не больше 3 запросов в любые 10 сек

запросы:   0     2     5     9
           ●-----●-----●-----●
           └────── 9 сек ─────┘   4 запроса за 9 < 10 → нарушение ✗

запросы:   0     2     5        12
           ●-----●-----●--------●
           └────── 12 сек ──────┘  4 запроса за 12 ≥ 10 → ok ✓

проверка на каждый новый запрос t:
  t − (таймстемп K запросов назад) < W ?  → нарушение
```

**TL;DR:** «≤ K запросов в любом окне W» проверяется одним сравнением на событие: новый запрос нарушает лимит ⇔ запрос, который был K назад, случился меньше W назад. Хранить нужно только последние K таймстемпов на ключ.

## Задача

Отсортированный по времени поток `(t, endpoint)`. Проверить: на каждый endpoint ≤ K запросов в **любом** промежутке длины W. (Реальный вопрос с собеса XTX Markets.)

## Ключевая редукция: любое окно → окна на событиях

Окон континуум (окно двигается непрерывно), но максимум счётчика достигается на окне, **правый край которого = какое-то событие**: сдвиг окна вправо до следующего события счётчик не увеличивает. → Достаточно N проверок: на каждое событие «сколько запросов в `(t−W, t]`».

## Критерий нарушения

Нарушение = K+1 запросов уместились в отрезок < W. Новый запрос в `t` — «лишний K+1-й» ⇔ запрос на K позиций назад был меньше W назад:

```
t − t[−K] < W  →  нарушение
```

Отсюда память: нужны только **последние K таймстемпов** на ключ (кольцевой буфер). Всё старше — уже не может участвовать в нарушении с будущими событиями.

```python
rings = defaultdict(lambda: [None] * K)   # endpoint → кольцо K таймстемпов
pos   = defaultdict(int)

for t, ep in events:                      # events отсортированы по t
    ring, i = rings[ep], pos[ep] % K
    if ring[i] is not None and t - ring[i] < W:
        report(t, ep)                     # K+1 запросов в окне W
    ring[i] = t
    pos[ep] += 1
```

- Время: O(1) на событие → O(N) суммарно (нижняя граница: каждую строку надо прочитать)
- Память: O(E·K), E = число ключей

## Граничная семантика — уточнить, не угадать

- `t − t[−K] < W` = полуинтервал `(t−W, t]`
- замкнутое окно `[t−W, t]` → условие `≤ W`
- пример на грани: K=2, W=5, запросы `1 3 7 8` → при `8`: `8−3 = 5`. Полуинтервал — ok, замкнутое — нарушение

## Что проговорить на собесе

- одинаковые таймстемпы — алгоритм корректен автоматически (секундная гранулярность лога)
- форма ответа: bool / первое нарушение / все → определяет возможность early-exit
- поток не отсортирован (несколько машин, clock skew) → буферизация с watermark, кольцо ломается
- масштабирование: ключи независимы → шардинг по endpoint (Kafka partition by key)
- альтернативы и когда кольцо не годится → [[rate-limiter-algorithms]]
